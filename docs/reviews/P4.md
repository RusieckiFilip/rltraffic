## Findings, and what was done about each

### MAJOR-1 — the online inference path was unprotected · **FIXED**

Three mutations of `agent/DTAgent.py` survived all 58 tests **and each moves the reported number**
(measured by the reviewer on `(seed 101, draw 1000)`, true value 106.456150):

| mutation | suite | ATT |
|---|---|---|
| `_normalise_state` returns the raw state | 58 passed | **138.971318 (+32.5)** |
| `_window` forgets `/ rtg_scale` | 58 passed | **110.267512 (+3.8)** — most of the margin to 110.861 |
| `_window` writes timestep 0 everywhere | 58 passed | **107.162162 (+0.7)** |

Nothing compared `DTAgent._window`'s inference-time window against
`TrajectoryWindowDataset.__getitem__`'s training-time window, and **no test ever constructed a
`DTAgent` with `stats=`**, so the normalisation branch executed zero times. The shipped code was
verified correct by hand; the defect was the absence of the guard.

**Fix:** `tests/test_dt_agent.py::test_the_inference_window_equals_the_training_window_for_the_same_history`.
It spies on the model's `forward` and asserts, for every step of a real episode, that what `act()`
feeds the model equals `dataset[i]` exactly. Exact by construction: `target_rtg` is set to the
episode's own total return so the agent's forward recursion must land on the loader's backward
one; `rtg_scale` is a power of two so scaling is exact; the fixture's rewards are integral.
**All three mutations now fail it.**

### MAJOR-2 — the Wilcoxon's two correction terms had zero coverage · **FIXED**

Deleting the tie correction **or** the continuity correction left `tests/test_dt_gate.py` at 32
passed. Every Wilcoxon assertion was on `w_plus`/`w_minus`/`statistic` or an inequality on `p`;
nothing pinned `z` or `p` — while those p-values go in the paper.

**Fix:** `test_wilcoxon_z_and_p_match_a_variance_derived_from_first_principles`, using a *different
derivation* rather than a copy of the implementation's expression: under the null each signed rank
contributes ±`r_i` with probability ½, so `Var(W+) = Σ r_i² / 4`, which with average ranks
automatically carries the tie correction (50.375, against 51.0 with no ties). **Both deletions now
fail it.**

### MAJOR-3 — `p4_gate.json` claimed MaxPressure ran from a checkpoint · **FIXED**

`_cell()` hardcoded `policy_source: "checkpoint"`; `_run_baselines` patched it afterwards, but
`_run_evaluate` rebuilt the baseline cells through `_cell()` and lost the correction. The two
committed artifacts contradicted each other about how the same 100 episodes were produced, and
the **gate** artifact — the one P4.4 is told to reuse — was the wrong one. Queue item 0b exists
exactly to make this field trustworthy.

**Fix:** `policy_source_for(arm)` derives it from the arm; `_cell` refuses a cell straddling two
arms; the artifact was regenerated. Guarded by two tests.

### MAJOR-4 — the promised configuration artifact did not exist · **FIXED**

`docs/plans/p4.md` promised `docs/data/p4_dt_config.json` and `PREREGISTRATION.md` §6.2 requires
the frozen configuration "as a committed artifact, not as prose". It was absent, and the full
config existed only inside the **gitignored** checkpoints.

**Fix:** `config_artifact()` reads it **back out of a trained checkpoint** (evidence, not
constants) and `train` now emits it. Writing it immediately exposed **MINOR-4**: the checkpoint's
own `declared_gradient_steps` says 40000, because `train_dt` was re-invoked with the raised
budget, so the artifact would have stated that we declared what we actually raised to. The budget
block is therefore taken from the **training artifact**, which is the only record carrying the
true declaration, and it now reads `declared 20000 / raise_to 40000 / raise_taken true /
reported 40000` with an explicit `budget_source`.

### MAJOR-5 — the declared-step guard was vacuous in the run that produced the number · **FIXED**

`_run_evaluate` set `steps = training["reported_gradient_steps"]` and never read its own
`--steps`, which was dead. So `load_gate_checkpoint` compared 40000 to 40000: it could catch a
stale checkpoint file but never "you reported a budget other than the declared one".

**Fix:** `expected_reported_steps(training, declared=)` makes the **declaration** the input and
the artifact the thing checked — the artifact's own declared budget must match, and the reported
count must be the declaration or, only if the raise was recorded as taken, `raise_to`. `--steps`
is now live and passed at 20000. Guarded by a test covering four rejection paths.

### Minors accepted and acted on

- **MINOR-1 — undisclosed, and now disclosed.** At evaluation the scaled RTG input runs
  **−0.577 … +0.153**, and **75/360 = 20.8 % of decisions are conditioned on a *positive* RTG**,
  which cannot occur in training (all rewards ≤ 0 ⇒ all training RTG ≤ 0). Every episode ends
  conditioned outside the training support. Added to the packet's limitations.
- **MINOR-2 — evidence *for* the run, recorded.** The reviewer probed the conditioning on
  `(101, 1000)`: `target_rtg = 0.0` gives **102.05** and `−3000` gives **102.41**, against
  **106.46** for the declared `−5762`. **The declared, un-tuned rule is not the best RTG**, so the
  reported number is demonstrably not RTG-optimised. Material for P4.3.
- **MINOR-3 — packet corrected.** The single remaining skip is
  `test_corpus_format_check.py: datasets/ is not present in this working tree`, not a SUMO skip.
- **MINOR-5 — fixed.** `p4_gate.json` now records `env_settings`, `engine_seed`,
  `declared_gradient_steps` and a **sha256 per checkpoint**, so the gate can be tied to specific
  weights by a future reader.

### Minors recorded but NOT acted on, with reasons

- **MINOR-4** (checkpoints' own `declared_gradient_steps` = 40000): mitigated in the config
  artifact rather than in the checkpoints, because fixing it at source means retraining and the
  training artifact already carries the truth. **A checkpoint travelling alone still cannot show
  that a pre-declared raise was taken.**
- **MINOR-6** (`_run_train` indexes `stacked["rtg"]` by dataset index): correct only because
  `stack_dataset(dataset)` refuses a multi-group dataset, which it does loudly. A latent trap when
  P5/cologne3 passes `group=` — flagged for P5.
- **MINOR-7** (500-episode CIs pool 5 seeds × 100 draws): already disclosed as Limitation 8; the
  Wilcoxon correctly uses per-draw means, so no inferential claim is affected.
- **MINOR-8** (§6 checkboxes): deliberate — the merge commit ticks them.

## The reviewer's own list of tests that are theatre

Recorded because it is more useful than a list of passing tests:

- `test_an_all_false_attention_mask_still_produces_finite_output` — passes with or without the
  diagonal guard; on this backend SDPA cannot produce the NaN it guards against.

  place only through trap B.
- `test_the_evaluation_pool_is_the_whole_registered_held_out_range` and
  `test_no_evaluation_draw_can_be_a_training_draw` — both compare two constants and say nothing
  about the pipeline.

  detect a wrong variance (proved).

These are left in place: they are cheap and they pin conventions. They are listed so nobody counts
them as coverage.
