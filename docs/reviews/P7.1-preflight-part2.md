The chunks hold the data. (By reading; the truncation operator is unconditional.)
3. **Lock self-exclusion is incomplete for a matching invocation** (check 4b, `selfmatch_run.out`): with the driver's own argv0 set to `python -m <module> DRIVER-SELF`, it refused with exit 3 naming pid = driver pid + 2 — a fork of the driver (the `$(...)` subshell / pipeline child) that inherits the argv and is neither `$$` nor `$PPID` (driver.sh:133). In the documented invocation `bash <path>` the argv contains neither `python` nor the module, and runs 3b/3d/3e all passed the lock — the pattern's `python` prefix, not the exclusion, is what protects it.
4. **Non-interactive launch silently disables the INT trap.** Started as an async job of a non-interactive shell (`nohup … &`, from a script) bash inherits SIGINT ignored and `trap on_signal INT` is not installed (observed in the first, invalid 3b run: driver alive, no FAILED after the group SIGINT). TERM is still trapped (3e). SIGHUP (tmux `kill-session`) is not trapped: no FAILED record would be written (by reading). Launch it as the header says — foreground in tmux.
5. **Predicate edge cases, hand-edit only:** `observer: "false"` (JSON string) is truthy → skipped (exp1 `1h-observer-string-false`, `:1681`); a chunk with **no** `regime` key under the parity name is read as parity under the same format version (`1i-regime-key-absent`, `:1683/:1699`). No writer at this commit produces either.
6. **`report` on a row with `n_teleports: null`** raises an uncaught `TypeError` traceback (exp2 `2h`) — non-zero exit, so fail-closed in the driver, but not a `REFUSED:` message. A missing key is caught (`REFUSED: 'n_teleports'`).
7. **Stage order differs from D4's listing:** driver runs smoke → A1 → A1b → A2 → A4 → report; D4 lists A1, A1b, A2, A4, smoke, report. Harmless (smoke fails fastest); noted because the test `test_the_driver_runs_every_stage_amendment_d4_names` pins presence, not order.
8. **The lock counts any process whose command line literally contains the pattern** — e.g. a reviewer's `bash -c '… python -m offline.sumo_att_reference …'` or a heredoc — and refuses with exit 3, nothing consumed. Benign (fail-closed), but the operator should expect it while other sessions are active.
