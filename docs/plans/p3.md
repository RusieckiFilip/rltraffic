## 1. What is being built

A PyTorch `Dataset` over the existing episode corpus, yielding **one intersection's context window**
per item:

```
rtg (K,1) float32 · state (K,D) float32 · action (K,) int64
avail_mask (K,A) bool · timestep (K,) int64 · attention_mask (K,) bool
```

Plus frozen normalisation statistics (P3.2) and draw-aware splitting (D4). No model, no training loop,
no RTG conditioning strategy — those are P4 (brief §4).

**Deliverables**
- `offline/dataset.py` — the loader, stats, and the group-aware collate helper.
- `tests/test_offline_dataset.py` — synthetic fixtures; always runs, no corpus needed.
- `tests/test_offline_dataset_corpus.py` — real-corpus tests; skip-gated, so the Return Packet can
  report **ran vs skipped** separately (§7 D1).
- `docs/returns/P3.md`.

## 3. Design

### 3.1 One reader, not two (§7 C-3)

`offline.trajectory_logger.load_episode` is the only reader. This module never calls `np.load` on an
episode file. Today `load_episode` accepts `"1.0"` only; P2.6's committed plan adds
`SUPPORTED_FORMAT_VERSIONS = ("1.0", "1.1")` and returns `None` for the ATT field on v1.0. So:

- **ATT gating is delegated**, not reimplemented. This module reads `getattr(episode, "att_per_step", None)`
  and stores it per episode. On today's `main` the attribute does not exist → `None`; after P2.6 merges,
  v1.0 files give `None` from `load_episode` itself and v1.1 files give the array. Either way this
  module has exactly one behaviour and no version branch of its own.
- The field is never named `average_travel_time` — `tests/test_offline_naming_guard.py` is an AST scan
  over `offline/**` that rejects the bare registry name as an attribute, bound name, keyword arg or
  dict-literal key.
- **Version homogeneity is still enforced here**: a dataset instance spanning both v1.0 and v1.1
  manifests raises. BRIEF_08 §5 forbids mixing the two corpora, and the loader is where P4 would
  otherwise mix them silently.

### 3.2 RTG — the definition, and why the accumulation order is part of it

> `rtg[t] = Σ_{u=t..T-1} local_reward[u]` — undiscounted, **inclusive of `r_t`**, over that
> intersection's own `ix{i}_local_reward` stream (purely local: the corpus was collected at
> `global_reward_weight = 0.0`), so `rtg[t]` pairs with **state row `t` and action row `t`**, and
> `rtg[T-1] == r_{T-1}` exactly.

Implementation: an explicit **reverse accumulation loop in float64**, cast to float32 for storage.
Two deliberate choices:

- **A different code path from the test's.** The test recomputes with `np.cumsum` on the reversed
  array (brief §3.2 requires exactly that, and requires it not go through the loader's helper). If the
  loader also called `np.cumsum`, the "independent route" would be the same numpy reduction twice.
- **The same summation order as that route**, so the comparison is `==` on float32 and never
  `allclose`. Both accumulate from the last element backwards; for float64 that is bit-identical.
  The cost is Python-level iteration — measured at ~360 steps per (episode, intersection); for the
  largest realistic training set (grid4x4, 7 tiers, 400 episodes each, 16 intersections) that is
  ~16 M iterations, seconds, against a construction that already decompresses gigabytes.

A third route, `math.fsum` (exactly rounded), is used in the tests as a cross-check. It agrees
bit-exactly only when the rewards are integer-valued; the corpus's `queue_length` rewards are, and the
test **asserts that precondition** rather than assuming it, so the day a non-integer reward enters the
corpus the test says so instead of silently loosening.

### 3.3 Items, windows, padding

- Item enumeration: every `(episode, intersection, t)` with `t ∈ [0, T-1]`. Observation row `T` is
  **never** an input — it has no action and no reward. That is how truncation is honoured: nothing is
  treated as absorbing, no terminal zero is appended (C6, and `terminated` is hardcoded `False`).
- The window ending at `t` covers rows `t-K+1 … t`, **left-padded** when `t+1 < K`.
- Padded positions are **all zero**: `state` 0.0, `rtg` 0.0, `action` 0, `timestep` 0,
  `avail_mask` all-False, `attention_mask` False. This follows the brief verbatim. It has one known
  sharp edge, recorded here rather than silently: **a padded `action` of 0 is indistinguishable from a
  real action 0 without the mask**, so any loss that forgets `attention_mask` trains on fabricated
  zero-actions. Padding with `-1` would make that crash instead; the brief says zero, so zero it is,
  and the sharp edge goes to P4 in the Return Packet.
- `timestep` carries the absolute row index `t` (for the DT's timestep embedding), 0 on padding.

### 3.4 Splits (D4, registered in `PREREGISTRATION.md` §5)

| split | draw ids |
|---|---|
| `nominal` | `{0}` — preserves source vehicle order; never pooled with randomised draws |
| `train` | `1 … 999` |
| `heldout` | `1000 … 1099` — never in any training corpus, for any method |

- `draw_ids=` narrows within the split and must be a **subset** of it; anything else raises.
- An episode whose manifest draw falls outside the requested split **raises** — never skipped. Ruled
  in §7 D2 and the reason is the one that matters: a leak that raises is a bug, a leak that skips is a
  published number.
- The corpus contains draws 1–200 only, so the held-out rule is **satisfied trivially today**. It is
  implemented anyway because it is unbuyable after the fact.
- The draw id comes from the manifest, and is **cross-checked against the `.npz`'s own `flow_draw`
  scalar** on load; a mismatch raises. Two recorded sources, one comparison — the cheapest possible
  double-compute on the quantity the whole split rests on.
- Episode files are taken from the manifest's `episodes[*].filename`, never from `glob` ("ask by draw
  id, never by file order"). A listed file missing on disk raises; an unlisted `.npz` present on disk
  raises. Measured: manifest and disk agree in 69/69 dirs today, so neither check fires on this corpus.

### 3.5 Normalisation statistics (P3.2, with §7 D3's two additions)

Granularity: per `(scenario_id, intersection_id)`. `scenario_id` comes from the manifest's
`run_metadata`; intersections differ in `state_dim` across scenarios and within cologne3.

- `state_mean`, `state_std` over **observation rows 0 … T-1** of every included episode (the rows that
  are actually fed to the model), `ddof=0`, accumulated in float64, **stored float32**.
- Applied as `(state - mean) / where(std > 0, std, 1.0)`, **before** padding, so padded rows stay
  exactly 0.0 rather than `-mean/std`. `normalize=True` by default; passing `stats=` reuses frozen
  statistics and skips fitting entirely.
- **Fitted on the training split only** (§7 D3). `save_stats()` records `split`, the exact
  `draw_ids` fitted on, and the dataset directories. Statistics fitted on held-out data are test-set
  leakage — quieter than training on it, and exactly what an offline-RL reviewer looks for. Moot today
  (only draws 1–200 exist); unbuyable later.
- **RTG summary recorded, nothing applied** (§7 D3): per `(scenario_id, intersection_id)`,
  `min / max / mean / std` and quantiles `10/25/50/75/90/95/99` of the RTG values over all included
  `(episode, t)`. P4.3 prompts in quantile space; computing them there from a second code path is how
  two pipelines start disagreeing.
- JSON round-trip is **exact**: float32 values are widened to Python floats, whose `repr` round-trips.
  A test asserts byte-identity of `save → load → save`.

### 3.6 Heterogeneous intersections (§7 D5)

`.groups: dict[(state_dim, n_actions), list[int]]` is exposed; there is no `require_homogeneous`
switch, because cologne3 is a headline scenario and a hard raise would delete it. C6 forbids padding
across intersections and this module does not.

Mixing groups in one batch **already fails loudly** — `torch.utils.data.default_collate` raises when
it tries to stack tensors of different shapes. That is a mechanical guarantee and the docstring says
so as one. Because torch's message names tensor shapes but not the intersections behind them, this
module also ships `collate_windows(items)`: it checks the `(D, A)` pair first and raises an error
**naming both shapes and the intersection ids that produced them**, then delegates to
`default_collate`. Someone will hit this assembling batches in P5.

### 3.7 API surface (frozen by this plan)

```python
DRAW_SPLITS: dict[str, tuple[int, int]]        # "nominal" | "train" | "heldout" -> inclusive range

@dataclass(frozen=True)
class WindowMeta:                              # what item_meta(i) returns
    dataset_dir: str; episode_file: str; scenario_id: str
    ix_id: str; ix_index: int; t: int; flow_draw: int

@dataclass(frozen=True)
class RtgSummary:  min, max, mean, std, quantiles  # descriptive only

@dataclass(frozen=True)
class NormalizationStats:
    stats_version: str; split: str; draw_ids: tuple[int, ...]; dataset_dirs: tuple[str, ...]
    state_mean / state_std / row_count / rtg: nested {scenario_id: {ix_id: ...}}

class TrajectoryWindowDataset(torch.utils.data.Dataset):
    def __init__(self, dataset_dirs, *, context_length, split="train",
                 draw_ids=None, stats=None, normalize=True) -> None
    def __len__(self) -> int
    def __getitem__(self, index) -> dict[str, torch.Tensor]     # the six keys, nothing else
    def item_meta(self, index) -> WindowMeta
    @property
    def groups(self) -> dict[tuple[int, int], list[int]]
    @property
    def stats(self) -> NormalizationStats

def save_stats(stats, path) -> None             # atomic: tmp file + rename, after validation
def load_stats(path) -> NormalizationStats
def collate_windows(items) -> dict[str, torch.Tensor]
```

`item_meta` carries the episode file path, intersection id and `t` (§7 D4), so any downstream
disagreement traces back to a row on disk.

**Filesystem-mutation barrier.** The dataset writes nothing at all. `save_stats` is the only writer:
it validates fully, writes a temporary file in the destination directory, then renames. A failed save
leaves the previous file untouched and creates no directories.

**Memory.** Construction keeps, per episode, only the per-intersection `state / avail_mask / action /
local_reward` arrays plus the computed RTG; lane and metric arrays are dropped after `load_episode`
returns. Measured order of magnitude: ~1 MB per grid4x4 episode retained, so a 400-episode tier is
~0.4 GB and the full 4800-episode corpus is a few GB — fine on 64 GB, and P4 loads one tier.

## 4. Discriminating power — the new requirement, applied

The ruling: *every alignment or invariant test must report the distance between the correct answer and
the deliberately wrong one, not only its pass rate.* Measured over **2 episodes per dataset dir = 138
episodes, all 69 dirs, all 7 tiers, 3 scenarios** (920 intersection streams, 331 200 decision rows):

**RTG off-by-one.** `rtg_correct[t] − rtg_offbyone[t] == r_t` exactly, so the mutation is invisible at
every row where `r_t == 0`:

| scenario | streams | rows | rows where `r_t == 0` (blind) | mean \|r_t\| | max \|r_t\| |
|---|---|---|---|---|---|
| cityflow1x1 | 46 | 16 560 | **0.83 %** | 45.5 | 209 |
| cityflow_cologne3 | 138 | 49 680 | **25.31 %** | 9.65 | 82 |
| cityflow_grid4x4 | 736 | 264 960 | **37.63 %** | 9.17 | 135 |

Per-row, then, the RTG identity is blind on a quarter to a third of grid4x4 and cologne3 rows. **The
array-level assertion is not**, and that is the form the test takes:

| scenario | streams with **no** discriminating row | worst stream: rows that differ | worst stream: max \|Δ\| |
|---|---|---|---|
| cityflow1x1 | 0 / 46 | 357 / 360 | 35.0 |
| cityflow_cologne3 | 0 / 138 | 92 / 360 | 4.0 |
| cityflow_grid4x4 | 0 / 736 | 68 / 360 | 3.0 |

So: **0 blind streams in 920**, and the weakest stream in the corpus still disagrees at 68 of 360 rows
with a maximum gap of 3.0. The test therefore asserts **whole-array equality**, never a sampled row,
and the Return Packet reports these numbers rather than "it passed".

**State-row off-by-one** (would a shifted state window be visible?): consecutive state rows are
identical at 0.10 % of rows on hz1x1, 10.97 % on cologne3, 13.74 % on grid4x4; **0 / 920 streams** are
entirely constant, and the worst stream still changes at 112 of 360 rows.

**Consequence, stated plainly:** on grid4x4 and cologne3 the identity checks are weak per row, so
**the mutation tests carry the weight**, exactly as the ruling anticipates. Both mandated mutations are
run against the real corpus as well as the fixtures, and both margins are reported.

## 5. Test plan (red first, then implementation)

Written against a **signature-only skeleton raising `NotImplementedError`**, so every test reaches the
real API surface and fails on its own assertion path rather than on one shared `ImportError`.

### 5.1 `tests/test_offline_dataset.py` — synthetic, always runs

Fixture: a hand-written corpus directory (episode `.npz` + `manifest.json`) with
- `ix_ids` deliberately **not** sorted, and ids chosen so env order and lexicographic order disagree;
- different `state_dim` and `n_actions` per intersection (never padded across);
- **per-intersection distinct reward streams**, so a positional mix-up changes the numbers;
- `avail_mask` with genuinely mixed True/False, and the taken action always available;
- non-constant state values (a constant fixture would satisfy an alignment assertion by construction —
  the §7 tautology rule);
- values chosen exactly representable in float32, so `==` is meaningful.

**Fixture-validity control:** `load_episode` reads the fixture and returns arrays identical to what was
written. Without this, the fixture proves only that the loader agrees with my idea of the format.

Tests:
1. `rtg` equals `np.cumsum` on the reversed reward array, whole array, `==`.
2. `rtg` equals the `math.fsum` route (third path), with the integer-valued precondition asserted.
3. `rtg[T-1] == r[T-1]`, and `rtg[0] ==` the stream total.
4. Off-by-one RTG is **detected**: the same comparison helper rejects a deliberately shifted array, and
   the report includes how many rows differ (so the check cannot be silently blind).
5. Window content equals the raw rows for a full window and for a partial one.
6. Padding: mask marks exactly the real steps; every padded position is zero / False.
7. Shapes and dtypes of all six keys.
8. ID keying: the item for a given `ix_id` carries **that** intersection's arrays, on the unsorted
   fixture; and the sorted-position answer is shown to be different (so the test is not vacuous).
9. Truncation: exactly `T` items per (episode, intersection); no item reads observation row `T`.
10. Determinism: two constructions, same indices → byte-identical tensors; and a seeded `DataLoader`
    with `shuffle=True` gives byte-identical batch sequences across two runs.
11. Held-out refusal: `split="train", draw_ids=[1000]` raises `ValueError`, `match=` on "held-out".
12. Draw 0 is refused by `train` and accepted by `nominal`.
13. Out-of-split draws present in a directory raise (never skipped), and the message names the ids.
14. Manifest/`.npz` draw mismatch raises.
15. Stats: mean/std recomputed independently and compared `==` on exactly-representable fixture data;
    stats frozen (a second dataset given `stats=` does not refit); JSON round-trip byte-identical;
    RTG quantiles present for every `(scenario, ix)`.
16. Stats record the split and the exact draw ids fitted on.
17. Version gating: v1.0 corpus → ATT field `None`; a mixed-version corpus raises.
18. NaN local rewards raise.
19. Groups: `.groups` splits the heterogeneous fixture correctly; `collate_windows` raises naming both
    `(D, A)` shapes and the intersection ids; `default_collate` on a straddling batch raises too.
20. Barrier: a failed `save_stats` leaves the previous file byte-identical and creates no directory.

### 5.2 `tests/test_offline_dataset_corpus.py` — real corpus, skip-gated

Located via `RLTRAFFIC_CORPUS`, else `<repo>/datasets`; `pytest.skip` **with a reason naming the

22. The **off-by-one margin on real data**, reported per scenario: number of differing rows and max

## 6. `avail_mask` — a claim constraint, not a test problem

Measured: **460 / 460** per-intersection mask streams in 69 episodes (1 per dataset dir, all 7 tiers)
are entirely `True`. Mechanism, verified in source: the corpus was collected with
`control_mode: acyclic`, and `envs/phase_control.py:583` `AcyclicPhases.available_actions()` returns
every green phase.

So **action masking never binds anywhere in our data.** Masking stays in the model (the env raises on
illegal actions, and masks will bind under cyclic modes and P6 lane closures), but:

- a no-mask ablation on this corpus would measure nothing;
- the paper must not credit masked-action modelling as a learned capability;
- "the mask never excludes the taken action" is, on this corpus, **true by construction** — asserting
  it is a tautology. The corpus test therefore asserts the *falsifiable population claim* ("every
  stored mask is all-True") and the loader's mask handling is tested on a synthetic fixture where the
  mask genuinely binds.

This goes in the Return Packet under its own heading so P4/P5 inherit it (§7 C-2).

## 10. Risks and limitations to carry into the Return Packet

- **Padded action 0 is a real action.** Any P4 loss that ignores `attention_mask` trains on fabricated
  zero-actions without crashing. Recorded in §3.3; the brief mandates zero padding.
- **v1.1 is untested here.** Until P2.6 merges, the ATT gate can only be verified in its `None` branch;
  a v1.1 file cannot be read by `load_episode` on `main`. Stated as a limitation, not papered over.
- **The mutation tests carry the weight on grid4x4 and cologne3** (§4), where per-row discriminating
  power is 62–75 %.
- **`ix_ids` is sorted in all three real scenarios**, so ID-keying correctness is proven only on the
  synthetic fixture. That is a property of the corpus, not of the test.
- **Open question for the coordinator:** should the loader expose a per-intersection index map
  (`indices_by_intersection`)? P4/P5 will want it; it is derivable from `item_meta` in three lines, so
  it is left out under the scope fence rather than added speculatively.
