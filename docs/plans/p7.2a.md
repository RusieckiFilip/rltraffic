## 3. The artifact

### 3.1 Layout (additive, inside the draw)

```
<out_root>/cityflow1x1/draw_NNNN/          <- PARENT. Read. Never written by this phase.
    flow.json  cityflow.json  routes.rou.xml  provenance.json
    parity/                                 <- the only thing this phase creates
        routes.rou.xml        parent rendering + parity <vType> bound to every vehicle
        noteleport.sumocfg    net-file relative to the SHIPPED net; time-to-teleport -1
        provenance.json       materialised-draw-parity/1.0 (section 3.2)
```

**Why a subdirectory and not files beside the parent's four** — `_existing_conflict`
(`offline/materialise_draws.py:606`) builds

```python
present = {path.name for path in target.iterdir() if path.is_file()}
```

so a **subdirectory is invisible to the parent's identity check**, while any new *file* in the draw
directory would make every future `materialise()` refuse with `it holds unexpected file(s)` (`:609`).
The layout is therefore forced by the existing code, not chosen for taste.

**Format version:** `materialised-draw-parity/1.0`, declared in the module docstring beside
`materialised-draw/1.0`.
**Alignment convention (unchanged, and restated in the docstring):** vehicle ids are `0..n-1` in
`startTime` order and `depart = startTime + <begin>` written with two decimals — that is
`flow_randomizer.render_sumo`'s convention (`:535-540`), inherited element for element. The parity
step changes **only** the `<vType>` element and the `type=` attribute of each `<vehicle>`;
`_verify_rendered_rou` (`offline/parity.py:305`) re-parses and proves ids, departures and routes
survive.

### 3.2 `parity/provenance.json`

Written with the existing `_provenance_bytes` (sorted keys, no wall clock, trailing newline) so
"this re-run was a no-op" stays checkable by byte equality.

| field | value |
|---|---|
| `format_version` | `"materialised-draw-parity/1.0"` |
| `scenario_key`, `draw_id`, `pool` | copied from the parent's provenance |
| `parent` | `{flow_sha256, routes_sha256, provenance_sha256}` — the parent files **as found on disk** |
| `parity_contract_version`, `vtype_id`, `vtype_attributes` | `"1.0"`, `"cf_parity"`, `parity.parity_vtype_attributes()` |
| `files` | `{routes.rou.xml, noteleport.sumocfg}` → sha256 of the bytes written (the parity provenance itself is excluded, matching the parent's convention) |
| `net` | `{reference (as written, relative), resolved (repo-relative), sha256}` of the **shipped** `.net.xml` |
| `sumocfg` | `{begin: 0, end: 4000, time_to_teleport: -1}` as written |
| `demand_audit` | `{n_cityflow, n_sumo, multiset_equal, n_index_aligned_equal, order_matches, depart_range_cityflow, depart_range_sumo, depart_offset}` |
| `n_vehicles`, `n_bound` | from the re-parse of the rendered text; must be equal |
| `git_commit`, `git_dirty` | non-identity fields, as in the parent |

`demand_audit` is CAP(E) **on this draw**: `conversion_audit.demand_from_cityflow_flow(parent
flow.json)` against `conversion_audit.demand_from_route_file(parity routes)`, with every SUMO depart
shifted back by `<begin>` before comparing. Both extractors return document-order
`list[tuple[float, tuple[str, ...]]]` and neither sorts, so the multiset and the index-aligned count
are two genuinely different questions. I add `depart_offset` to the brief's field list because the
shift is the one step that could silently make a mismatch look like a match, and a reader cannot
re-derive it from the other fields.

**Refusal conditions (validation, before anything is written for *any* draw):** `multiset_equal` is
not `True`; `n_bound != n_vehicles`; `flow_json_disagreements(parent flow.json)` is non-empty.
`order_matches` is **recorded, never required** — expected `True` everywhere (measured `True` on five
existing draws, fact 5), and it is the cheap thing to notice if it ever is not.

## 4. The algorithm, phase by phase

`materialise_parity(source_config, draw_ids, *, out_root, force=False, dry_run=False,
allow_worktree=False) -> list[ParityResult]`

### Phase 0 — refusals that need no filesystem at all
1. `out_root` inside a **linked worktree** → refuse unless `allow_worktree=True` (§4.2).
2. ids checked through the existing `_checked_draw_ids` (negatives and duplicates refused).
3. source config exists and is a CityFlow sim config; `scenario_key = scenario_key_for_config(...)`.
4. `_sumo_pairing(source)` must return a pairing; an unpaired scenario is refused with its own
   `sumo_skipped_reason` — there is nothing to bind and a silent skip is how a transfer measurement
   ends up running `DEFAULT_VEHTYPE`.

### Phase 1 — parents, through the existing `materialise()` and no second rendering path
`materialise(source_config, ids, out_root=root, dry_run=dry_run)` — **never with `force`**, so a
parent that differs from what would be regenerated is refused by the existing code and this phase
never replaces one. For 0–5 and 1000–1099 this returns `kept`; for 201–300 it writes the parents
first. Under `dry_run` it writes nothing and the missing parents are reported as
`parent missing (would materialise)`.

### Phase 2 — validate every requested draw (read-only, no `mkdir`, no write)
Per draw: the parent holds exactly the four expected **files**; `flow.json` and `routes.rou.xml`
hash to the parent provenance's `files` entries; `provenance.sumo.vtype_bound is False` and the
unbound caveat text is present; `flow_json_disagreements(parent flow.json) == []`; the net reference
resolves to the shipped `.net.xml`; CAP(E) as in §3.2. **A parent that fails any of these is refused,
never repaired.**

### Phase 3 — build every byte in memory
`render_parity_rou_text(parent routes text)` (which self-verifies), then
`render_parity_sumocfg_text(net_rel, "routes.rou.xml", time_to_teleport=-1)`, then the provenance
record. No temp rendering directory is needed: unlike `_build_draw`, both helpers are **pure text
functions**.

### Phase 4 — classify
An existing `parity/` is compared the same way `_existing_conflict` compares a draw: the file-name
set, then the two rendered files byte-for-byte, then the provenance field by field with
`_NON_IDENTITY_FIELDS` excluded. Identical → `kept`. Different → **refused** with the first
differing name, unless `force=True`, in which case `replaced`. A refusal of any single draw aborts
the whole run before phase 5.

### Phase 5 — stage, then commit
Mirrors `_commit` (`offline/materialise_draws.py:644-686`), including its two load-bearing details:

```python
            aside: Path | None = None
            if target.exists():
                # Move aside rather than delete: the old draw survives until the new one
                # is in place, so a failure here cannot destroy prior data.
                aside = staging_root / f"aside__draw_{built.draw_id:04d}"
                os.replace(target, aside)
            try:
                os.replace(staged, target)
            except BaseException:
                if aside is not None:
                    os.replace(aside, target)
                raise
```

and the `finally: shutil.rmtree(staging_root, ignore_errors=True)` at `:685-686`. Staging lives
under `<out_root>/.staging-*`, i.e. the same filesystem, so every `os.replace` is atomic.

### 4.1 The target-path guard (brief §0.4, the reason a pre-flight exists)

`_commit`'s `os.replace(staged, target)` is one wrong `target` away from replacing a **draw**
instead of a parity subdirectory, and draws 1000–1099 are what every merged held-out number since
P4.6 resolves through (`DEFERRED` 55). So, in a **separate pre-pass over every plan before the first
rename**, each target must satisfy all three of:

1. `target.name == "parity"`;
2. `target.parent.name` matches `^draw_\d{4}$`;
3. `_checked_output_path(out_root, target)` — the existing containment check.

Any failure raises before a single rename happens. T7 plants a target that fails (1) and asserts both
the raise and an unchanged tree snapshot.

### 4.2 The worktree refusal (`DEFERRED` 55's rule, as a control)

> "any task that materialises into a gitignored path does it in the MAIN tree, never in its
> worktree" — `docs/notes/DEFERRED.md:83`

Walk up from `out_root.resolve()` to the filesystem root; at the first `.git` found: a **file** means
a linked worktree → refuse unless `allow_worktree=True`; a **directory** means the main tree → allow;
none found (e.g. `tmp_path`) → allow. Verified signal: fact 10. The CLI flag `--allow-worktree`
prints why it exists. Tests use `tmp_path`, and one test builds a fake `.git` *file* to see the
refusal fire.

### 4.3 Parents this task reads and never writes

`<out_root>/cityflow1x1/` — `draw_0000`–`draw_0005`, `draw_0201`–`draw_0300` (created by phase 1),
`draw_1000`–`draw_1099`: **206 directories, 4 files each**. Plus these repo files, read only:
`configs/sim/cityflow1x1.json`; and in `scenarios/hangzhou_1x1_bc-tyc_18041610_1h/` — `flow.json`,
`roadnet.json`, `hangzhou_1x1_bc-tyc_18041610_1h.sumocfg`, `.rou.xml`, `.net.xml`. The only
directories this task creates are the 206 `parity/` subdirectories and transient `.staging-*` roots.

## 5. `offline/parity.py` — one optional parameter, byte-identical default

```python
def render_parity_sumocfg_text(
    net_file_reference: str,
    route_file_reference: str,
    end_seconds: int = SUMO_END_SECONDS,
    *,
    time_to_teleport: int | None = None,
) -> str:
```

- `None` → **the current bytes, exactly**. The header sentence naming A15(c) is emitted **only when
  the parameter is not None**; emitting it unconditionally would change the default output and break
  `test_parity_rou_regenerates_byte_identically`'s sibling controls, which pin the committed P7.0
  artifacts.
- An integer → the block below is inserted after `</time>`, tab-indented to match the file:
  ```
  	<processing>
  		<time-to-teleport value="-1"/>
  	</processing>
  ```
- A **positive** value raises: it re-enables the mechanism A15(c) froze off. `0` is accepted (SUMO
  documents non-positive as disabling), and the value is echoed into the provenance, so what ran is
  never inferred from a default.
- New module constant `NOTELEPORT_SUMOCFG = DECLARED_PARITY_DIR / f"{DECLARED_PARITY_STEM}_noteleport.sumocfg"`,
  added to `__all__`, as the reference T5 reads.

`write_parity_scenario` is **not** touched: `test_write_parity_scenario_round_trips_into_a_clean_directory`
pins `set(written) == {"rou", "sumocfg"}`, and it has no reason to grow a third output here.
`flow_randomizer.render_sumo` is **not** touched (brief §3.4).

## 9. Conflicts found between the brief and the repo (repo wins)

1. **T2's `COLLECT_SETTINGS` cannot be passed to `make_env`.** The brief says "construct `SumoEnv`
   through `experiments.envs.make_env` with `COLLECT_SETTINGS`". `offline/transfer_gate.py:1028`
   defines `COLLECT_SETTINGS` as a **flat CLI argv tuple** (`"--max-steps", "360", ...`), while
   `make_env` takes an `EnvSpec` whose `settings` is a **fully resolved dict** and reads
   `max_steps`, `delta_time`, `global_reward_fn`, `local_reward_fn`, `global_reward_weight`,
   `control_mode`, `state_features`, `metrics`, `obs_norm`, `gui`, `libsumo` **without `.get`**.
   → **Plan:** build `dict(SETTING_DEFAULTS)` updated from `docs/data/p4_3_probe.json:env_settings`
   (read from the file, never retyped), which is the same setting set `COLLECT_SETTINGS` encodes and
   is exactly what P4.3 ran. This is Q1 below.
2. **`reset(seed=...)` does not seed SUMO with that number.** The brief's T2 says `reset(seed=1000)`.
   `BaseTrafficEnv.reset` reseeds the env RNG and passes a **drawn** `_engine_seed` to `--seed`
   (`envs/base_traffic_env.py:629-631`, `envs/sumo_env.py:182-183`); the `__init__` boot runs with no
   `--seed` at all. T2's assertions do not depend on the engine seed, so the call stays as written —
   but the packet will say what the seed did, because "seeded with 1000" would be false.
3. **`env._sumo` is the `traci` *module*, not a connection** (`envs/sumo_env.py:130`,
   `_import_sumo_api`). `env._sumo.vehicle.getTypeID(...)` works as the brief writes it; the
   consequence worth recording is that TraCI's connection is process-global, so T2 must hold exactly
   one SUMO env at a time.
4. **Minor.** The brief's §3.2 sketch omits `depart_offset`; I add it (§3.2, with the reason).

None of these changes what the task builds.

## 11. Risks I can name now

- **The 201–300 band may not reproduce P4.3.** That is the point of gate 5 and it is a stop
  condition, not a risk to manage: 100/100 exact or the band is not P4.3's and this task stops with

  the import check, by running in the main tree, and by the fact that a wrong `dir` makes existing
  draws refuse loudly (`cityflow.json differs byte-for-byte`) rather than pass quietly.
- **Sequencing:** `materialise()` for 201–300 writes ~100 parents before the parity phase validates
  them. A refusal at that point leaves the parents written and no `parity/` anywhere. That is
  additive and re-runnable, but it is **not** "nothing happened", and the packet will say so.
- **TraCI is process-global**, so T2 cannot run in parallel with another SUMO test in the same
  process. The suite is sequential today.
