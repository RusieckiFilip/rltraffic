## Context

Measured on real CityFlow (2026-07-27), engine seeds 1000 and 1001 produced byte-identical
trajectories with identical `episode_sha256` and identical return (−502.000). P1's logger records
`flow_draw` faithfully but always receives `None`, so a 20-episode corpus today is one trajectory
written 20 times while the manifest truthfully reports 20 episodes. **Without demand randomisation the
offline corpus carries almost no information**, and the MADT (P3/P4) would train on it.

The Explore phase confirmed the mechanism from source. CityFlow reads the flow file exactly once, in
the engine constructor (`CityFlow/src/engine/engine.cpp:65`, `loadFlow(dir + flowFile)`).
`Engine::reset()` (`:744-760`) clears the vehicle pools and calls `flow.reset()` on the already-parsed
in-memory `flows` vector — **it never re-reads the file** — and `resetRnd` only reseeds `rnd`, which
with `laneChange: false` and fully-specified routes has nothing observable left to influence. So
`reset(seed=X)` cannot change arrivals by construction, and varying the *vehicle list* is the only
lever. This task builds that lever.

**Acceptance bar (from the brief):** a corpus collected with the randomiser must produce distinct
`episode_sha256` values across draws, and the test suite must prove it.

## Decisions taken at GATE 1 (user-approved, 2026-07-28)

1. **`render_sumo` is real, not a `NotImplementedError`.** The brief's escape hatch was conditioned on
   being unable to establish a faithful id mapping; the mapping is verified to be the identity, so the
   hatch does not apply. It reuses the scenario's own `<vType>` block **verbatim** from a template
   `.rou.xml`. The three transforms never touch vehicle physics — only *which* vehicles depart and
   *when* — so the calibrated vType is exactly correct and **no CityFlow→SUMO physics mapping is
   invented**. (The rejected alternative, synthesising a vType from the flow.json vehicle block, would
   have silently dropped `usualPosAcc` / `usualNegAcc`, which have no SUMO counterpart.)
2. **`TrajectoryLogger` gains an additive `rebind_env()`.** A fresh env per draw is mandatory (see
   Context); one logger must serve the whole sweep, because a fresh logger per draw rewrites
   `manifest.json` from an empty list and orphans earlier draws' `.npz` files. `rebind_env` validates
   that the new env's `ix_ids` match the frozen ones, turning "all draws share one topology" into an
   enforced invariant instead of an assumption. `offline/` is our own code and is not frozen.
3. **`volume_scale` is a deterministic multiplier applied identically to every draw** (brief-faithful).
   Between-draw variation comes from *which* vehicles thinning removes and from jitter.

(`engine.cpp:65`), so an absolute `flowFile` is impossible and the drawn file must be reachable
relatively from `dir`. Planned mechanism: keep `dir` as the original scenario dir and set

byte-identical, so parsed topology is unchanged. The outcome goes in the Return Packet either way.

## `offline/flow_randomizer.py`

```python
@dataclass(frozen=True)
class FlowDraw:
    draw_id: int; seed: int; n_vehicles: int
    source_sha256: str; params: dict[str, float]

class FlowRandomizer:
    def __init__(self, source_flow_path, *, base_seed=1000,
                 jitter_sigma_s=30.0, thin_p=0.10, volume_scale=1.0): ...
    def draw(self, draw_id: int) -> tuple[list[dict], FlowDraw]: ...
    def render_cityflow(self, entries, out_path) -> Path: ...
    def render_sumo(self, entries, out_path, *, template_rou_path, depart_offset) -> Path: ...

def sumo_begin_from_sumocfg(path) -> float: ...   # module-level helper
```

`depart_offset` is **keyword-only with no default** and `sumo_begin_from_sumocfg` **raises** when
`<begin>` is absent or unparseable — see GATE-2 addition A. A defaulted `0.0` is exactly the shape a
silent scenario bug takes.

`base_seed` is added to the brief's `__init__` signature because brief requirement 2 specifies
`np.random.default_rng(base_seed + draw_id)`; `render_sumo` gains two keyword-only arguments because
neither the vType block nor the time base is derivable from a flow file alone. Both noted in the
Return Packet.

**Chosen defaults and the reasoning (goes verbatim in the module docstring).**
`jitter_sigma_s=30.0`, `thin_p=0.10`, `volume_scale=1.0`. On hangzhou's 2021 vehicles that removes a
*different* ~202 vehicles per draw and reshuffles every departure by N(0, 30 s) — a visibly different
demand pattern at roughly −10% volume, well short of pathological. Expected count is
`N · (1 − thin_p) · volume_scale`, so `thin_p` and `volume_scale < 1` compose multiplicatively.

**`draw_id == 0` is the identity** — an explicit early return before any RNG is constructed. Its
`FlowDraw.params` records `{jitter_sigma_s: 0.0, thin_p: 0.0, volume_scale: 1.0}`, because those are
the parameters *actually applied*, which keeps the manifest self-describing.

**Transform pipeline** (one `rng = np.random.default_rng(base_seed + draw_id)`, in this order):
1. **Bernoulli thinning** — keep entry *i* iff `rng.random(N)[i] >= thin_p`.
2. **Volume scaling** — `target = round(len(kept) * volume_scale)`; below → drop uniformly without
   replacement; above → sample the extras uniformly *with* replacement; equal → no-op. Relative order
   preserved.
3. **Departure jitter** — every surviving entry (duplicates included, each drawing its own sample, which
   is how brief req 2's "duplicates with fresh jittered start times" falls out of a single code path)
   gets `startTime += rng.normal(0, sigma)`, clipped at `>= 0`, then coerced back to the source
   entry's own numeric type. `endTime` is set equal to `startTime` (safe: verified 0/8305 entries have
   them unequal). `interval` and the whole `vehicle` block are copied unchanged.
4. **Stable sort** by `startTime`.

Jitter is applied last deliberately: it is the only transform whose output must be re-sorted, so
sorting once at the end is sufficient. Jitter is **not** clipped at the top of the horizon — a vehicle
pushed past 3600 s simply never appears, which is the honest outcome; clipping would pile vehicles up
on the boundary. With σ=30 against a 3600 s horizon this affects a handful of vehicles; documented.

**Never mutate the source** (req 3): `draw()` always returns freshly-built dicts, including for
`draw_id == 0`, so a caller mutating the result cannot reach the randomiser's parsed copy. No method
ever opens the source path for writing.

**Byte-exact `render_cityflow`** (req 4): the source's indent width and trailing-newline presence are
**sniffed from the raw bytes at construction**, and `render_cityflow` re-serialises with them.
Crucially, `__init__` then *verifies* the sniff by re-serialising the parsed source and comparing to
the original bytes, raising `ValueError` if they differ. This promotes req 4 from a test assertion to
a **construction-time invariant**: a `FlowRandomizer` that cannot reproduce its own source refuses to
exist. Cost is one ~1 MB serialisation (~10 ms). Note this means the byte-identity test exercises the
*general* render path, not a `copyfile` shortcut that would mask a broken renderer.

**`render_sumo`**: `xml.etree.ElementTree` (stdlib). Copies every `<vType>` from the template verbatim;
emits one `<vehicle>` per entry with `depart = f"{startTime + depart_offset:.2f}"`, sequential string
ids, and `<route edges="…"/>` from the entry's route joined by spaces. The template's `<vehicle>`
elements are inspected for a `type` attribute and that usage is **mirrored** — cologne carries
`type="pkw"`, hangzhou omits it (and therefore silently uses SUMO's `DEFAULT_VEHTYPE`); mirroring
reproduces each scenario's real behaviour rather than quietly "fixing" hangzhou. Output is sorted by
depart, as SUMO requires. Formatting via `ET.indent()` + `xml_declaration=True`; `render_sumo` carries
no byte-identity requirement (the brief imposes that on `render_cityflow` only).

## `offline/collect.py`

New flags, in a mutually exclusive group, default `None` → **today's simulation behaviour unchanged**
(no flow file materialised, `EnvSpec` untouched, `flow_draw=None`). The manifest is not byte-identical
to P1's, though: `run_metadata` gains six keys, all `null` on a nominal run except `numpy_version`.
`--flow-draw N` · `--flow-draws A B C` · `--flow-draws-range START END` (**half-open `[START, END)`**
per the GATE-2 ruling below, stated in the help text; a degenerate range raises rather than resolving
to no draws). Plus `--flow-jitter-sigma` (30.0), `--flow-thin-p` (0.10), `--flow-volume-scale` (1.0)
so the recorded parameters are real rather than hardcoded.

**Loop shape — draws outer, episodes inner**, because the env must be rebuilt per draw and not per
episode:

```
for draw_id in draw_ids:                       # [None] when no flag was given
    materialise <out_dir>/flows/flow_draw{N}.json  and  cityflow_draw{N}.json
    env = make_env(spec_for_draw)
    logger = TrajectoryLogger(env, …)  on the first draw, else logger.rebind_env(env)
    for i in range(episodes):
        engine_seed = base_seed + i            # restarts per draw, so the draw is the only variable
        … existing P1 body, with flow_draw=draw_id …
    env.close()
```

Episode seeds restart per draw deliberately: it makes the draw the sole varying factor across draws,
and P1's global monotonic episode counter plus the `_draw{N}` filename suffix means no collision.
Drawn flow files are **persisted under `<out_dir>/flows/`, not a tempdir**, so the exact demand behind
every episode stays inspectable and reproducible without re-running the randomiser.

`run_metadata` gains: `flow_draw_ids`, `flow_randomizer_params`, `flow_source_path`,
`flow_source_sha256` (all JSON-serialisable — the logger validates this at construction, `:332-338`).

**Scope fence:** `--flow-draw*` is wired for **cityflow only**. On `sumo`/`moss` it exits with a precise
message. SUMO collection would additionally need a rewritten `.sumocfg` and a `--flow-source-json`
flag to locate the CityFlow-format demand, which the brief does not ask for. `render_sumo` is real and
tested regardless, so claim C3's foundation is delivered; only the SUMO *collection* path is deferred.
Stated in the Return Packet.

## GATE 2 rulings (user, 2026-07-31) — these supersede the proposals above

**Q1 `rebind_env()` — APPROVED with three conditions**, all binding:
1. *Purely additive.* No existing behaviour, signature or default changes. **The 30 P1 tests must pass
   untouched — if any P1 test needs editing, STOP and report instead.**
2. It **must** verify the new env is topologically identical to the one the logger was constructed
   with: **same `ix_ids` in the same order, and same per-intersection `n_actions`**; `LoggerStateError`
   on any mismatch. Rationale: `lane_ids` are already guarded run-level via `lane_ids_sha256`, but
   `ix_ids` are not — this closes that gap. A redraw must never silently rebind onto a different
   topology.
3. Legal **only between episodes**, never mid-episode — enforced via the state machine (`_IDLE` only).

*Implementation note on condition 2.* `n_actions` is not captured at construction: P1 deliberately
defers `Utils.infer_action_counts` to `on_reset` because `env.action_space` does not exist until
`_setup_spaces()` has run. Capturing it in `__init__` would violate condition 1. `rebind_env`
therefore compares the new env's counts against `self._n_actions`, which `on_reset` maintains and
`finalize_episode` does **not** clear (`_clear_episode` runs at the *start* of `on_reset`), so the
previous episode's counts are still live at every legal call site. When no episode has run yet the
list is empty and only `ix_ids` are checked — documented in the docstring.

**Q2 SUMO collection — DEFER.** C3 is P7 and P7.0's early gate runs on nominal flow (draw 0), where
this is not needed. The Return Packet must carry **one explicit paragraph** stating what P7.3 still
needs — the `.sumocfg` writer and the `--flow-source-json` flag — so P7 reads it rather than
rediscovering the gap.

**Q3 `--flow-draws-range` is HALF-OPEN `[START, END)`**, matching `range()`; `--flow-draws-range 0 100`
is 100 draws. Stated in the `--help` text, **and** the run summary prints the resolved count and the
actual draw ids, so the ambiguity cannot survive to runtime.

**Q4 `flows/` persistence — confirmed.** The collector clears stale drawn-flow files **itself**, using
a **narrow pattern matching only the names it writes** — never a directory wipe. P1's NB3 applies
verbatim (`ep*.npz` once matched an unrelated `epoch_stats.npz`; narrowed to the exact written shape,
non-recursive). A user file that happens to live in `flows/` must survive. `flows/` is documented as
part of the run's output in the manifest.

**Addition A — the SUMO time base is parsed, never hardcoded.** `sumo_begin_from_sumocfg` reads each
scenario's `<begin>`; a hardcoded 25200 would silently break every future scenario. **If a paired
scenario has no readable `<begin>`, raise rather than defaulting.** Hence `depart_offset` has no
default.

**Addition B — the relpath convention is proven against a real engine before anything is built on it**,
and the proof goes in the Return Packet. **DONE, and it passes** — see §Pre-flight.

## Open questions for the GATE — ALL CLOSED at GATE 2

1. **`rebind_env()` touches `offline/trajectory_logger.py`, which the brief's file list does not
   mention.** It is not a frozen file and the change is purely additive, but it modifies a P1
   deliverable that has already been reviewed and merged. Approved at GATE 1; restated here as the
   audit trail.
2. **SUMO collection is deferred.** `render_sumo` is real and tested, but `--flow-draw` refuses
   non-CityFlow backends. If C3 needs an end-to-end SUMO collection run inside P2.0 rather than later,
   say so now — it is roughly a `--flow-source-json` flag plus a generated `.sumocfg`, not a redesign.
3. **`--flow-draws-range START END` is inclusive at both ends.** The brief does not specify. Flagging
   it because an off-by-one here silently changes how many episodes a reported corpus contains.
4. **Persisting drawn flows under `<out_dir>/flows/`** rather than a tempdir is a deliberate departure
   from the brief's "temp/working directory" wording, chosen for provenance. Note that P1's
   `_existing_run_files()` glob (`:384`) is non-recursive, so `--overwrite` will **not** clear a stale
   `flows/` subdirectory; the collector will therefore overwrite draw files by name rather than relying
   on that cleanup.
