### 5.1 The declared scenario

**`hangzhou_1x1_bc-tyc_18041610_1h`** — hangzhou 1×1 #1, `PREREGISTRATION` §4's first headline

Out of scope by `BRIEF_21` §6 and not run: grid4x4 (not paired), MOSS, cologne1, any DT, any training,
any transfer experiment, any change to the state feature set.

### 5.2 The cells

Six cells, `{cityflow, sumo} × {maxpressure, fixedtime, random}`, **5 episodes each**, driven by
`offline.collect` — merged, reviewed code that writes the v1.1 episode format — with settings held
identical across every cell except the backend and the policy:

```
--max-steps 360 --delta-time 10 --control-mode acyclic
--global-reward-fn queue_length --local-reward-fn queue_length --global-reward-weight 0.0
--state-features lane_vehicle_count lane_waiting phase_onehot
--fixed-time-k 4 --base-seed 1000 --episodes 5 --thread-num 1
cityflow: --env-config configs/sim/cityflow1x1.json
sumo:     --env-config scenarios/..._parity/..._parity.sumocfg
```

- **No flow draw is requested**, so both backends run the scenario's own nominal demand and
  `flow_draw` is recorded as absent. `D4`'s registered draw split governs *corpus* draws; this task
  collects no corpus and trains nothing, and says so rather than borrowing a band it does not use.
- `--base-seed 1000` sets **engine** seeds `1000…1004` (`offline/collect.py:722`). That is a different
  namespace from draw ids and is stated here so nobody reads it as the held-out draw band.
- `--global-reward-weight 0.0` is the registered collection convention (`PREREGISTRATION` §3.3).
- **Third policy, and why it is not scope creep.** With only the two anchors, ρ is 0 and 1 **by
  construction** in both backends and carries no information, so Branch A's "ρ transfers sensibly"
  would be untestable. `random` is the cheapest policy that gives ρ a value to compare and is already
  a registered ladder tier. Declared here, before any number.

### 5.3 The primary per-feature table — 16 features, reported per feature, never pooled

For the **MaxPressure** cells only (the probe policy C3's calibration is defined against), for each of
`intersection_1_1`'s **8 incoming lanes** and each of the two lane-derived state features
`lane_vehicle_count`, `lane_waiting_vehicle_count`:

- the sample is the **pooled T+1 = 361 observation rows of all 5 episodes** (row 0, the reset state,
  included), read from the episode `.npz` lane arrays, which the logger stores **keyed by sorted lane
  id** — so the two backends are aligned **by lane id**, never by position (§2 fact 7);
- **KS statistic** `D = max_t |F_cityflow(t) − F_sumo(t)|` over the pooled support, `F` the empirical
  CDF;
- **overlap coefficient** `OVL = Σ_v min(p_cityflow(v), p_sumo(v))` over the **exact integer support**.
  Both features are integer counts, so the pmf is exact and **there is no bin-width degree of
  freedom** — this is why the discrete form is declared rather than a kernel or histogram estimate.

**Reference noise floor, declared now:** with `n = m = 1805` pooled rows the KS 5 % critical value is
`1.358 · sqrt(2/1805) ≈ 0.0452`. The rows are autocorrelated and CityFlow's five MaxPressure episodes
are expected to be identical (deterministic policy, fixed demand), so the **effective** sample size is
smaller and is reported per cell as the number of **distinct** episodes. The floor is quoted as a
reading aid, never as a test.

**If the two incoming-lane SETS differ**, the symmetric difference is reported and the table is
restricted to the intersection, with the restriction named in the artifact. Declared in advance so it
is not a decision made while looking at the data.

### 5.4 The phase block — reported structurally, not as a KS number

`phase_onehot` has width 9 on CityFlow and 16 on SUMO (§2 fact 8), so a positional per-feature entry
would be meaningless. Reported instead:

- both widths, both green counts, and the **green-phase correspondence**: for each green action index
  `a`, the set of incoming lanes released by the phase `a` selects in each backend, compared as sets.
  This is what makes "action `a` means the same thing in both backends" checkable rather than assumed;
- the **overlap coefficient of the realised green-action distribution** under MaxPressure (8
  categories in both backends). **No KS statistic is reported for it** — KS on a categorical variable
  depends on an arbitrary category ordering, and inventing one would be a degree of freedom.

### 5.5 `DEFERRED` 18 — `average_travel_time` metric-set independence on SUMO, with its controls

Two sub-checks, because §2 fact 11 shows the question has a structural half and an empirical half.

- **18a (structural).** Construct `SumoEnv` requesting a metric set that does **not** contain
  `average_travel_time`, and assert it appears in `info["metrics"]` anyway — demonstrating
  `envs/sumo_env.py:119-125`'s unconditional union, i.e. that on SUMO the metric is never absent and
  `_track_completed` is therefore always true. **This is the honest scope limit of the check and it is
  reported as one: on SUMO the "metric not requested" case is unreachable through the env.**
- **18b (empirical).** One paired MaxPressure rollout, same `reset(seed=1000)`, same scenario, same
  360 steps, against a **1-metric** env (`metrics=["average_travel_time"]`, reward
  `average_travel_time` so nothing else is unioned in) and a **3-metric** env
  (`+ count_of_vehicles_completing_journey`, `+ waiting_time_all_vehicles_for_the_last_time_step_in_simulation`).
  Verdict by `np.array_equal` on the full 361-long ATT sequence.
  - **Vacuity control:** assert the two envs' `info["metrics"]` key sets genuinely differ and have
    sizes 1 and 3. Without it the check could pass by comparing an env with itself.
  - **Positive control:** a third rollout under a **different policy** must produce a sequence for
    which `np.array_equal` returns **False**, proving the comparison is capable of failing.

### 5.7 ρ, with both anchors

Per backend `b`, from the horizon metric `att_per_step[-1]` (`A1`), averaged over the 5 episodes:

```
Δ_b     = ATT_b(fixedtime) − ATT_b(maxpressure)
ρ_b(π)  = (ATT_b(fixedtime) − ATT_b(π)) / Δ_b
```

so ρ_b(fixedtime) = 0 and ρ_b(maxpressure) = 1 **by construction in each backend**, and the only ρ
carrying information is ρ_b(random). Every ATT cell is reported with `vehicle_count` at the horizon
(`A5`, unconditional) and with the per-episode spread. **No ATT is compared across backends anywhere
in this task** — the artifact records ATT per (backend, policy) so the within-backend arithmetic is
checkable, and every cross-backend statement is about ρ or about a distribution.

| **B3** | `#{i : D_i > 0.50} ≥ 9` (a majority of 16) | The shift is broad rather than confined to one feature. |
| **B4** | `sign(ρ_sumo(random)) ≠ sign(ρ_cityflow(random))` **or** `abs(ρ_sumo(random) − ρ_cityflow(random)) > 2.0 · M` | The normalised scale does not survive the crossing even in rank, or disagrees by more than a factor on CityFlow's own scale. A collapsed `Δ_sumo` also lands here, by inflating ρ_sumo. |

**Branch A fires if NO Branch-B criterion holds AND ALL of these hold:**

| id | criterion |
|---|---|
| **A1** | `Δ_cityflow > 0` **and** `Δ_sumo > 0` |
| **A2** | `min_i OVL_i ≥ 0.50` |
| **A3** | `#{i : D_i > 0.50} ≤ 4` **and** `max_i D_i ≤ 0.70` |
| **A4** | same sign **and** `abs(ρ_sumo(random) − ρ_cityflow(random)) ≤ 0.5 · M` |

**Branch C fires otherwise** — i.e. no B criterion holds and the A conjunction is not complete. The
rule is **total and mutually exclusive by construction** (A2 and B2 are disjoint; A3 and B3 are
disjoint; A1 is `¬B1`; A4 and B4 are disjoint), and the packet names **which criterion fired**.

**Thresholds, and the fact that they are conventions:** `OVL` 0.30/0.50 and `D` 0.50/0.70 are the
usual small/large reading points for these two statistics. They are **chosen**, not derived, and are
written down before any number precisely so the choice cannot be made while looking at the table. `M`'s
floor of 1.0 exists so a near-zero ρ_cityflow cannot force an unattainably tight band on ρ_sumo.

**Binding on the packet:** the branch is whatever the rule returns, evaluated by code, with the firing
criterion named. **P7.0 reports; it does not rule.** `BRIEF_04` §4.4's *"You do not decide the
go/no-go"* is not superseded by `BRIEF_21` and is honoured.

### 6.3 Margins — the coordinator's addition of 2026-08-16, made before any number exists

> *"B firing on `min OVL = 0.299` is a completely different result from `0.05`, and A missing on
> `max D = 0.71` is different from `0.95`. A branch verdict without its margin is the same defect as a
> p-value without an effect size — this project's own §7 rule that a check must report its
> discriminating power, applied to the gate itself."*

**Every criterion in §6.2 reports a row**, not only the one that fires:

| field | meaning |
|---|---|
| `statistic` | the quantity the criterion tests, in its own units |
| `threshold` | the declared boundary |
| `signed_distance` | `statistic − threshold`, **oriented so that a positive value means the criterion is satisfied in the non-pathological direction** (B not firing / A holding). Reported in the statistic's own units. |
| `fired` | boolean |
| `scale`, `relative_distance` | `signed_distance / scale`, for a cross-criterion reading only |

**Declared per-criterion scales**, fixed here so the normalisation is not chosen after the table:
B1/A1 → `Δ_cityflow` (the training-domain anchor span, the domain that does not move) ·
B2/A2 → `1.0` (`OVL` already lies on `[0, 1]`) · B3 and A3's count → `16` (the number of features) ·
A3's `max D` → `1.0` · B4/A4 → `M`.

**The packet then names two things: the criterion that fired with its distance, and the nearest
non-firing criterion with its distance.** ⚠️ **"Nearest" is ranked by `relative_distance` and is a
READING AID ONLY. The branch is decided by §6.2's raw criteria and by nothing else; the full
16-feature table and the full margin table are both reported, so any reader may rank them
differently without changing the verdict.**

**Two criteria have a discrete or boolean part and say so rather than manufacturing a margin:**
B3/A3's count is an integer over 16 features, and **B4's sign test has no continuous margin at all** —
when it fires on a sign flip the row reports `signed_distance: null` and prints both ρ values, because
inventing a distance for a boolean would be worse than reporting none.

### 11.1 Why the choice is nevertheless not outcome-driven

**The by-lane-id per-feature table of §5.3 is VOID — not unfavourable, VOID.** It yields **no branch**:

**The registered per-feature comparison is now the movement-paired alignment**: each CityFlow incoming

**Road level is retained as a diagnostic, not promoted**, for a stated reason: it is invariant to the
convention but coarser, and **its 8 features do not map onto thresholds written for 16** — B3 and
A3count are counts out of sixteen.
