## 3. What gets built

### 3.1 `offline/aligned_env.py` — the only door (A16)

```python
class AlignedEnv:
    def __init__(self, env: Any, alignment: ScenarioAlignment) -> None: ...
    def reset(self, **kwargs) -> dict[str, Any]:     # align_info(self._env.reset(**kwargs))
    def step(self, action) -> tuple[Any, bool, bool, dict[str, Any]]:
    def close(self) -> None: ...
    @property max_steps / intersections / action_space      # forwarded explicitly
    def __getattr__(self, name): return getattr(self._env, name)
```

**Forwarded explicitly, and why those six.** `reset` and `step` are the two that *change* (they align
the info) and must not be reachable by accident through `__getattr__`; `close` is forwarded because
the caller owns the env's lifetime and a missed `close` leaks a SUMO process; `max_steps`,
`intersections` and `action_space` are forwarded because they are exactly what the two consumers
read — `horizon_rollout` uses `env.max_steps` (`:81`) and `DTAgent.__init__` (through
`agent_with_target` → `load_gate_checkpoint` → `DTAgent.from_checkpoint`) uses `.intersections` and
`.action_space`. Naming them is the point: a reader can see the whole surface the DT path touches
without tracing `__getattr__`. Everything else — `_sumo`, `_engine_seed`, `close`-adjacent internals
— falls through `__getattr__`, which is what lets the probe's engine reads work on a wrapped env too.

**Two refusals at construction.**
1. **Not a SUMO env** → refuse. The check is `isinstance(env, envs.sumo_env.SumoEnv)` (imported
   lazily, so the module imports without traci). I prefer this to the config path's suffix because a
   CityFlow env can be handed a `.sumocfg` string and the *class* is what determines the info's shape;
   the suffix would accept the one case that matters and reject nothing.
2. **Wrapping an `AlignedEnv`** → refuse. `align_info` already refuses a second application
   (`backend_alignment.py:375-381`, on the state width), but it does so at the first `reset`, which is
   after the DT has been constructed and an env process started. Surfacing it in `__init__` turns a
   confusing mid-rollout failure into a one-line refusal.

`aligned_sumo_env_for_draw(scenario_key, draw_id, *, out_root, arm)` builds the env through A17's
route and wraps it with `alignment_for_scenario("hangzhou_1x1_bc-tyc", cityflow_roadnet=…,
sumo_net=…)`. The two network paths come from the repo's shipped scenario directory; no artifact of
P7.0/P7.1 is read. No on-disk format, so no format version — the docstring cites A16 rather than
restating the convention.

### 3.2 `offline/transfer_calibration.py` — A17(a), (b), (d) executed

Artifact `docs/data/p7_2b_calibration.json`, **format version `p7.2b-calibration/1.0`**, written by
`report` from per-draw chunks under `output/p7_2b/`.

**(1) `run_sumo_probe(draw_ids, *, out_root, engine_seed=1000, work_dir)`** — the SUMO twin of
`run_probe`. It mirrors `rtg_calibration.run_probe:406-419` line for line (fresh env, `reset(seed=…)`,
`agent.act(info)` → `env.step`, post-step infos accumulated, break on terminate/truncate, `samples[-1]`
for the horizon reading) and differs in exactly three declared ways, each because A17(b) requires it:
the env is SUMO; the two routes are **compared** (`run_probe` records both and leaves the comparison
to its caller); and four engine reads are taken per episode. A single failure refuses the draw **and**
the run.

Per-draw chunk `output/p7_2b/probe_draw_0NNN.json`:

```
format_version "p7.2b-calibration/1.0"     draw_id            scenario_key "cityflow1x1"
local_return  local_return_from_lanes  two_routes_agree      att_horizon
horizon_vehicle_count   decisions                            n_teleports
vehicle_types_seen (sorted)             time_to_teleport_option ("-1", read from the engine)
engine_seed_requested (1000)            engine_seed_drawn    (env._engine_seed)
config_path  config_sha256              seconds              canary_seconds
git_commit   git_dirty
```

**(2) Statistics and targets.** For `k ∈ PROBE_K_VALUES` and `S ∈ PROBE_STATISTICS` (both reused):
`S(R_sumo, k)` via `probe_statistic` over the first k rows; `S_cityflow` **read** from
`budgets[f"k{k}"]["statistics"][S]`; per subject `R_best` and `rtg_scale` read from the seed-101
payload (`ck["target_rtg"]`, `ck["rtg_scale"]`) and asserted equal across all five seeds;
`rule_b_target(best_source_return=R_best, probe_source_stat=S_cf, probe_target_stat=S_sumo)`;
`rule_a_target(R_sumo_returns, q)` for `q ∈ {1.0} ∪ SECONDARY_QUANTILES`; naive `= R_best`.
**Rule B / `mean` / k = 100 is `registered_prompt`; every other target is `ablation`.**

**(3) The in-support diagnostic.** `training_rtg_range(checkpoint)` (reused) gives `[min, max]`; the
target's position is `below` / `inside` / `above` with the margin. It is arithmetic — no rollout — and
it **never selects** (A8). Double-computed: the position is also obtained by calling
`in_support_counts([target], rtg_min=…, rtg_max=…)` and the two must agree, so the arithmetic is
checked against the registered function rather than trusted.

**(4) The smoke, fenced.** `smoke(subject, draw_id=5)` → `aligned_sumo_env_for_draw` →
`agent_with_target(env, seed-101 ckpt, declared_gradient_steps=40000, target_rtg=<registered prompt>)`
→ `horizon_rollout(env, choose, episodes=1, seed=1000)` with `choose(env, info)` recording
`agent.current_rtg()` per decision. **Recorded:** `decisions == 360`, `rtg_first == target`,
`rtg_last`, `n_decisions_in_support`, every action in `[0, 8)`, the engine-read type and regime,
`seconds`. **Fenced:** `horizon_rollout` returns `att_horizon` **and `episode_reward`** — I propose
putting **both** under `fenced_do_not_report`, because an episode return is as much a zero-shot
number as an ATT (§10 Q3). `report` refuses to copy that key into `docs/data/`.

**(5) `report`.** Writes the artifact from the chunks. Refuses: a missing or duplicated draw; a
two-route disagreement; a non-zero teleport count; a type set other than `{"cf_parity"}`; a chunk of a
different `format_version`; a source-statistics sha that differs from the one the chunks recorded; and
any attempt to emit `fenced_do_not_report`. **Every refusal precedes every write**, and the write is
`write_json_atomic` (reused from `dt_gate`).

chunk is moved to `output/p7_2b/failed/` rather than overwritten.

## 9. Conflicts and corrections found (repo/A17 wins; flagged, not silently absorbed)

1. **`mix50`'s "training RTG range" is the SPLIT range, not the training set's.** The checkpoint's
   `stats.rtg[cityflow1x1][intersection_1_1]` is `[−40294, −6]` over **216,000** rows (600 streams ×
   360), while `target_rtg −5959` and `rtg_scale 40223` come from the **training set** (200 streams ×
   360 = 72,000 rows = `tiers.mix50.training_windows`); indeed `rtg_scale 40223 ≠ |−40294|`. For
   `mappo1000` the two coincide (`9991 == |−9991|`), which is why it has never mattered. **A17(c)
   registered `[−40294, −6]`**, so that is the number I report — but I will name the field
   `support_range_over_the_split` with the row count beside it, so the packet cannot be read as
   claiming a 72,000-row training range. Q1.
2. **Two different "mix50 training draws" exist and only one is right.** The mix50 *checkpoint*'s
   `provenance.training_draw_ids` is `1..200` — byte-equal to **mappo1000's** list — while the tier's
   own list is `p4_7_declaration.json:tiers.mix50.training_draws`, **n = 152**, min 2, max 199. The
   brief names the declaration, which is correct; I record the trap here because reading the
   checkpoint would look natural and would silently weaken the disjointness assertion.
3. **The read order's parenthetical is wrong about one instrument.** It sends me to
   `make_observer_sumo_env` for "the engine-read counters: teleports, vehicle type". Teleports are
   there (through `SumoObservationRecorder`); **vehicle type is not** — `grep -c getTypeID
   offline/sumo_att_reference.py` is **0**. I do not use the observer at all: §3.2.1 prescribes the
   plain env and per-step `getStartingTeleportIDList`, and the observer would cost P7.1's measured

4. **`run_probe` does not check that the two return routes agree**; it records both and leaves the
   comparison to its caller (`rtg_calibration.py:421-433`). A17(b) requires agreement under `==`, so
   `run_sumo_probe` performs the check itself. Stated because "mirrors `run_probe`" could otherwise be
   read as inheriting a check that is not there.
5. **"The §7 canary" has no §7.** `BRIEF_36` line 6 and `BRIEF_35` D3.1 both call it that;

## 11. Risks

- **A probe episode that teleports or shows a non-`cf_parity` vehicle refuses the whole run.** That is
  A17(b) and it is right, but it means one bad draw stops 100. The resume rule makes the restart cheap
  (complete clean chunks are kept), and the failure would be a real finding about the P7.2a artifacts.
- **`agent_with_target` loads each checkpoint twice** (`load_gate_checkpoint` and again for
  `rtg_scale`); at two smoke episodes this is irrelevant, and I note it only so the packet's timings
  are not mistaken for model-loading cost.
- **The fence is a discipline, not a mechanism, until `report` enforces it.** Until then any print
  statement could leak a zero-shot number. I will write the fence into `report` first, before the
  smoke exists, so the enforcing code precedes the code that produces the fenced value.
