### 0.2 The naive in-domain rule's two quantities, and how the test recomputes them

A18(a): *`target_rtg` = the maximum episode return of the training set and `rtg_scale` = the largest
absolute RTG of the training set.* Both already have exactly one implementation in this repository —
P4's, at `offline/dt_gate.py:1381-1387`:

```python
summary    = dataset.stats.rtg[scenario_id][ix_id]
rtg_scale  = max(abs(summary.min), abs(summary.max))
target_rtg = max(float(stacked["rtg"][index][-1, 0])
                 for index in range(len(dataset)) if dataset.item_meta(index).t == 0)
```

`target_rtg`'s form is only readable once the padding convention is known: `__getitem__`
(`dataset.py:789`) puts padding **on the left**, so a window at `t = 0` has `span = 1` and
`start = context - 1`, which makes `rtg[-1, 0]` the RTG at decision 0 — the **whole episode's
return**. The maximum over all `t == 0` windows is the maximum episode return. `naive_in_domain_prompt`
is this computation lifted out of `_run_train` into a named function so a test can reach it; it is
not a new rule.

**The independent route the test uses touches neither function.** It opens each `.npz` with
`np.load`, reads `ix0_local_reward` (float64), forms `rtg = np.cumsum(r[::-1])[::-1]`, and takes
`max(rtg[0] over episodes)` and `max(|rtg|)` over the concatenation. It never constructs a
`TrajectoryWindowDataset`, never calls `stack_dataset`, and never reads `stats.rtg`.

**Run now on the 100 episodes that exist, asserted with `==` and not `allclose`:**

```

stats.rtg summary min -25257.0 max -71.0
INDEPENDENT: max episode return -20809.0  max|RTG| 25257.0
MATCH target True  scale True
```

Both exact. ⚠️ **These are half-corpus values and are NOT the anchor's prompt.** The anchor trains on
200 episodes; `target_rtg` is a max, so it can only rise or stay equal when 301–400 is added, and
`rtg_scale` likewise. The committed numbers come from the campaign, not from here.
