## 2. Tier choice: `mappo1000` (confirmed by the §8 ruling)

The gate threshold is defined *relative to the best online policy* (`1.05 ×`), so only the 105–107
tiers contain trajectories at the required quality: mappo200 is 125.03 and would demand a >12%
improvement over its own behaviour policy before the gate could even be reached. A failure from a
weaker tier is **uninterpretable** — pipeline defect or data ceiling, with no way to tell them apart.
P4.2 is a pipeline-capability gate; "does sequence modelling beat imitation" is registered as P4.4's
question.

**Two things this choice forbids me from claiming, carried into the Return Packet verbatim:**

1. Passing demonstrates **pipeline capability, not that sequence modelling beats imitation.**
2. Expert-only data has the **narrowest state coverage** in the ladder, so a pass says nothing about
   off-distribution behaviour.

## 3. The frozen configuration — declared here, before any training

Per `PREREGISTRATION.md` §6.2 this configuration becomes the project's configuration for every later
scenario, tier, perturbation and backend. It is recorded as a committed artifact
(`docs/data/p4_dt_config.json`, emitted by the tool) as well as in this file.

### 3.1 Model

| Key | Value | Source |
|---|---|---|
| `n_layer` | 3 | published DT (Chen et al. 2021) Gym configuration |
| `n_head` | 1 | published DT Gym configuration |
| `d_model` | 128 | published DT Gym configuration |
| `context_length K` | 20 | published DT Gym configuration; also the top of H4's registered sweep |
| `dropout` | 0.1 | published DT Gym configuration |
| `max_ep_len` | 360 | the scenario's `max_steps`; asserted against every `timestep` |
| token order per step | `(RTG_t, s_t, a_t)` | standard DT; `a_t` is predicted from the **state** token at position `t` |

Nothing here was chosen by looking at a result, and nothing is swept. **The deviation from the
published recipe is the step count**, and it is declared in §3.3 with its reason.

### 3.2 Optimisation

AdamW, `lr = 1e-4`, `weight_decay = 1e-4`, linear warmup over the first **1000** steps, gradient-norm
clip **0.25**, batch size **64**, loss `cross_entropy(..., ignore_index = PAD_ACTION = -1)`.
Batches are drawn **uniformly with replacement** over the 72,000 windows using a `numpy.random.
Generator` seeded from the training seed. All items lie in one `(25, 8)` group, so no batch can
straddle two intersection shapes.

**Training seeds: 101, 202, 303, 404, 505** — the project's existing seed set (the MAPPO tiers use
it), so DT seeds and MAPPO seeds are the same five labels.

### 3.3 The declared gradient-step count — **20,000**

20,000 steps × batch 64 = 1.28 M sampled windows ≈ **17.8 epochs** over the 72,000 windows.
The published DT trains 10⁵ steps on D4RL sets roughly 14× larger; the reduction is declared here in
advance and is the only departure from that recipe.

**The reported checkpoint is the one at step 20,000. Not a better one, not an earlier one.**

**The one pre-declared raise (§8 ruling, mirroring amendment A3).** If the training loss has not
plateaued at 20k, the budget is raised **once** to **40,000** steps, for **all five seeds**, and the
reported checkpoint becomes step 40,000. The criterion is mechanical and reads the **training curve
only** — no evaluation number may enter it:

> Split the run into windows of **2000 gradient steps** (10 windows at 20k). Let `L(w)` be the mean
> training loss over window `w`. Seed `s` has **plateaued** iff
> `|L(w_final) − L(w_final−1)| / |L(w_final−1)| < 0.05` **and**
> `|L(w_final−1) − L(w_final−2)| / |L(w_final−2)| < 0.05`.
> The run has plateaued iff **all five seeds** have (the strict direction A3 resolved for the same
> ambiguity: a procedure that plateaus on 4 of 5 seeds has not reliably plateaued).

The decision, the ten window means per seed, and the resulting `declared_gradient_steps` go into the
artifact. **A second raise is not available to this task.** The raise, if taken, happens before any
evaluation rollout is executed, and the tool refuses to evaluate a checkpoint whose recorded step
count differs from the declared one.

### 3.4 Return-to-go conditioning — one rule, no sweep

P4.3 owns the sweep and the probe calibration; this task needs exactly one conditioning rule and
declares it now:

- **`target_rtg` = the maximum episode return in the training split** = `max_i rtg_i[t=0]`.
  Measured on the `mappo1000` tier: **−5762.0** (200 episodes; min −9991.0, mean −7105.1).
  This is DTLight's `max_offline_return × scale` with `scale = 1.0`, i.e. the un-tuned default.
- **`rtg_scale` = `max(|rtg|)` over the training split = 9991.0**, from `NormalizationStats.rtg`
  (fitted on the training split only). Model input is `rtg / rtg_scale ∈ [−1, 0]`.
- At evaluation, `RTG_0 = target_rtg` and `RTG_{t+1} = RTG_t − r_t`, where `r_t` is read from
  `info["intersections"][ix]["reward"]` of the info returned by step `t` (F9). This is exactly the
  quantity the corpus stores as `local_reward` (F5 proves the two are the same stream), and it is
  consistent with the loader's `rtg[t] = Σ_{k≥t} r_k`.
- **State normalisation at evaluation uses the frozen training statistics**, carried in the
  checkpoint and also written through `offline.dataset.save_stats`. Refitting at evaluation time is
  the leakage the loader's docstring exists to prevent.
- **Action selection at evaluation is greedy (`explore=False`, argmax over masked logits).** Declared
  in advance because a stochastic policy would add a variance source the CIs would then have to
  absorb.

## 4. The evaluation protocol (binding, from the §8 ruling)

### 4.1 The gate cell

- **Draws: all 100 registered held-out draws `1000–1099`.** The whole pool, not a slice — using it as
  registered removes a selection rather than making one. §8's registered minimum is 20.
- **Arms, all measured live on those same draws, paired by draw id:**
  | arm | seeds | episodes |
  |---|---|---|
  | MADT (this task) | 5 training seeds | 5 × 100 = 500 |
  | MaxPressure | deterministic, no seed | 100 |
  | MAPPO@1000 | the 5 existing checkpoints | 5 × 100 = 500 |
  | *MAPPO@500 (declared diagnostic, see §4.4)* | 5 checkpoints | 5 × 100 = 500 |
- **Metric:** `att_horizon` through `offline.horizon_metric.horizon_rollout`, called with
  `episodes=1` per (arm, seed, draw). At `episodes=1` the reader's `final_vehicle_count` is that one
  episode's value, so **P8.0 finding B2 — a last-episode `final_completed` mixed with a mean
  `final_vehicle_count` — cannot arise here.** `final_completed` is not used at all.
- **Co-report (A5, unconditional):** `vehicle_count` at the horizon beside every ATT cell, plus the
  **draw ids** of every cell. All arms share the identical 100-draw set by construction, so no
  comparison is void and none needs recomputation over an intersection.
- **Engine seed 1000 for every rollout** (`horizon_rollout(seed=1000, episodes=1)`), matching the
  corpus's `base_seed`. On CityFlow the engine seed changes nothing observable once demand is fixed
  (`PREREGISTRATION.md` §5, verified empirically by P2.0); holding it constant keeps the arms
  comparable and the run reproducible.
- **`policy_source = "checkpoint"`** is recorded for every arm that has one (MADT, MAPPO@1000,
  MAPPO@500), per queue item 0b. Nothing here retrains anything. `offline/rederive_anchors.py` — where
  finding B1 lives — is **not touched**: `horizon_rollout` takes a `choose_action` closure, so a saved
  checkpoint evaluates through it with no change to any existing module.

### 4.2 Statistics

- Mean ± **95% CI** per arm (`1.96 × sd / √n`, `ddof=1`), matching `offline/att_ladder.py`'s
  convention so the numbers are commensurable with the committed ladder.
- **Paired Wilcoxon signed-rank** over the 100 shared draws, MADT vs each baseline, reported beside
  the inequalities (§8 point 5). scipy is unavailable (F11), so it is implemented here in
  numpy/stdlib: signed ranks with average ranks for ties, zero differences dropped (Wilcoxon's own
  convention), normal approximation with tie and continuity correction at `n ≥ 20`. It is tested
  against a hand-computed example and against a case with ties, and the statistic is double-computed
  by an independent route in the test.
- The DT's per-draw value for pairing is the **mean over its 5 training seeds** on that draw, so both
  registered variance sources (§8: training seed and evaluation draw) are reported, and the paired
  test is over draws.

### 4.3 The verdict

Computed on the held-out cell and stated plainly as **PASS** or **FAIL** before any interpretation:

```
Gate A:  ATT_MADT ≤ ATT_MaxPressure            (held-out, 100 shared draws)
Gate B:  ATT_MADT ≤ 1.05 × ATT_MAPPO@1000      (held-out, 100 shared draws)
PASS  ⇔  Gate A ∧ Gate B
```

`≤` is used exactly as registered — equality passes.

**Secondary, labelled, never the verdict:** the DT evaluated on the 200 **training** draws 1–200 and
compared against the committed ladder cells over the identical 200 draws, and against **110.73**.
This is an in-sample-demand reading; it is reported because it is the comparison against the
committed ladder and the brief's number, and it is labelled as such in every table it appears in.

### 4.4 One addition I am making, declared rather than silent

The registered gate says `ATT_best_online`; the §8 ruling instantiates that as MAPPO@1000. On draws
1–200 MAPPO@1000 (105.46) does beat MAPPO@500 (107.50) — but that ordering is measured on the
training pool, and **if it inverted on the held-out pool the ruled threshold would be looser than
"best online"**. I therefore measure **MAPPO@500 on the same 100 draws as a declared diagnostic**
(≈4 minutes), committed in the same pre-training artifact as the thresholds.

- The **gate verdict is computed exactly as ruled**, against MAPPO@1000.
- If MAPPO@500 comes out lower, the verdict against `1.05 × min(...)` is reported as an explicitly
  labelled secondary line and raised as an open question for the coordinator.
- Nothing is chosen after seeing a DT number: the diagnostic is committed before the first gradient
  step alongside everything else.

### 4.5 Held-out purity

Training uses `TrajectoryWindowDataset(..., split="train")`, which raises on any draw outside 1–999,
so a held-out draw cannot enter training even by mistake. The artifact additionally asserts
`set(train_draw_ids) ∩ set(eval_draw_ids) == ∅` and records both sets. The evaluation draws are
**never** loaded through the dataset at all — they are materialised demand, run live.

### 4.6 Demand provenance for the evaluation draws

Draws 1000–1099 are materialised with `offline.materialise_draws` into this worktree's gitignored
`scenarios/draws/` (identity is `(base_seed=1000, draw_id)`, pinned by that module to the
`flow_randomizer` constants). Two free cross-checks, both asserted rather than trusted:

1. Draws 1000–1004 already exist in the main checkout's pool; the newly materialised files must be
   **byte-identical** to them (the module's own idempotence rule ignores only `git_commit`/`git_dirty`).
2. For the secondary cell, a materialised training draw's flow digest is compared against the
   corpus manifest's `flow_draw_sha256` entry for the same id. If those two agree, the demand behind
   the secondary evaluation is provably the demand the corpus was collected on. **If they disagree I
   stop and report** — it would mean the collection path and the materialisation path disagree about
   what a draw is, which is a finding, not a detail to route around.

## 6. Deliverables — two source files, as the brief's fence requires

### 6.1 `agent/DTAgent.py`

Causal GPT-style DT over `(RTG, state, action)` tokens with a `BaseAgent`-compatible `act()`.
Constructor mirrors `agent/MAPPOAgent.py`'s shape, read from source, not inferred:
`__init__(self, gym_env, *, context_length=20, n_layer=3, n_head=1, d_model=128, dropout=0.1,
max_ep_len=360, target_rtg=None, rtg_scale=None, stats=None, device=None, seed=None)`.

- Reads `env.intersections`, uses `Utils.infer_action_counts`, `Utils.resolve_device`,
  `Utils.seed_everything`, `Utils.extract_per_intersection_info`, `Utils.state_from_info`,
  `Utils.extract_valid_actions` — reused, never reimplemented (CLAUDE.md rule 5).
- **One model, one context buffer per intersection, keyed by intersection id, never by index**
  (P1.4b's carried note). Requires a homogeneous `(state_dim, n_actions)` set and raises naming both
  shapes otherwise. With one intersection this is exactly the required behaviour; keying by id is
  what stops P5 inheriting a silent positional bug. This is **not** spatial mixing — the
  intersections do not see each other.
- `act(info, explore=True, update_memory=True)` → `np.ndarray[int64]`, ordered by
  `[ix.id for ix in env.intersections]` (contract C1). New episode detected by `info["step"] == 0`;
  RTG advanced from `info["intersections"][ix]["reward"]` (F9). `update_memory=False` leaves the
  context untouched, matching MAPPO's documented meaning for interleaved evaluation.
- If the reward key is absent at `step > 0`, `act()` **raises** rather than silently freezing the
  RTG at its target — a frozen RTG would still produce plausible actions and a plausible number.
- `observe(...)` satisfies the BaseAgent contract by recording the last info/reward; it does **not**
  advance the RTG, because `act()` is the single route and two routes would double-decrement. This is
  stated in the docstring and asserted by a test.
- `save(path)` / `load(path)`: weights + full config + normalisation statistics + `target_rtg` +
  `rtg_scale` + provenance (tier, training draw ids, declared steps, seed, device, torch/CUDA
  versions). `load()` validates `(state_dim, n_actions)` against the env **before adopting any
  state**, so a rejected checkpoint leaves the agent as it was — the in-memory form of the
  filesystem-mutation barrier, mirroring `MAPPOAgent.load`'s C8 check.
- Docstring states the **format version** and the **alignment convention** explicitly (§3 of
  CLAUDE.md), including which token predicts which action.

### 6.2 `offline/dt_gate.py`

CLI + library: build the training dataset, train, checkpoint, evaluate every arm, emit artifacts.

- `python -m offline.dt_gate baselines` — measure the baseline arms on the held-out pool and write
  the pre-training threshold artifact. Runs with **no DT in existence**.
- `python -m offline.dt_gate train` — train the 5 seeds, apply the §3.3 plateau rule, save
  checkpoints + stats.
- `python -m offline.dt_gate evaluate` — evaluate the saved checkpoints and emit the gate artifact

- Filesystem-mutation barrier throughout: every artifact is validated, built in memory, then written

- No `experiments.runner` import anywhere — importing it pins the calling process to one torch
  thread as a process-global side effect (§10 of the plan). Only `experiments.config` and

Artifacts (JSON, committed): `docs/data/p4_dt_config.json`, `docs/data/p4_heldout_thresholds.json`,

## 8. The three traps, and what is done about them

1. **Fully-masked attention rows.** Left padding + causal masking leaves the first query position
   with no attendable key; softmax over an all-`-inf` row is `NaN`, and `NaN` survives
   `ignore_index` into the backward pass as `0 × NaN`. **Fix: the diagonal is always attendable.**
   Guarded by T6.
2. **All-`False` `avail_mask` on padded rows.** Masking logits there produces the same all-`-inf`
   row. **Fix: apply the availability mask only to rows with at least one legal action.** Guarded by
   T7.
3. **`-1` is a loss target, not an embedding input** (the §8 ruling's correction to brief §2).
   `nn.Embedding` cannot take `-1`. **Fix: the action *input* uses a dedicated pad index `A`
   (`nn.Embedding(A+1)`), while the loss *target* keeps `-1` so `ignore_index=-1` stays the
   tripwire.** Guarded by T4 (target) and T2 (correspondence).
