### 0.2 The collector's seeding path, answered from the code

```python
:717   rng = np.random.default_rng(int(args.base_seed))       # the POLICY rng, re-seeded per draw
```

**Therefore: `--base-seed 1000 --episodes 1` gives `index = 0` → `engine_seed = 1000` →

and the driver (§3.6) passes those literally rather than relying on a default. The plan makes that a
driver-text assertion in T9, not a comment.

### 0.3 A17(f)'s identity, argued from both routes

A17(f) demands the logged episode's return equal `probe[draw].local_return` **bit-for-bit**. Two
independent code paths produce those two numbers, and the claim is that they are **the same
definition**, not merely two numbers that happen to agree.

| | probe route | logger route |
|---|---|---|
| source | `info["intersections"][ix]["reward"]` of each **post-step** info | the same field of the same post-step info |
| code | `rewards.append(float(payload["reward"]))` — `offline/rtg_calibration.py:345`, inside `episode_return_two_routes` | `value = float(payload["reward"]) …; self._out_local_reward[i].append(value)` — `offline/trajectory_logger.py:794-795` |
| aggregation | `sum(rewards)` → `local_return` (float64) | stored as `ix{i}_local_reward`, summed by the gate |
| C6 | post-step infos only; the reset info carries no reward | identical: `on_step_result` is the only appender |

**Same expression, same object, same order, one intersection on hz1x1** — so
`sum(ix0_local_reward) == probe.local_return` is an identity, not a coincidence. The probe's own
second route (`local_return_from_lanes`, recomputed from `lane_waiting_vehicle_count`) is what makes
the *arithmetic* trustworthy; this identity is what makes the *gate* mean something.

⚠️ **One hazard, and it is a real one: the logger stores float32.**
`trajectory_logger.py:118` declares `ix{i}_local_reward` as `(T,) float32`, and `_rows_1d` casts.
The probe accumulates in Python float (float64). A float32 round-trip is **not** generally
bit-identical to float64, so `==` could fail for a reason that is neither a wiring defect nor an
engine difference.

**Measured, not assumed:** over 6 episodes × 3 intersections × 360 steps = **6,480 stored values** of
the committed `datasets_v11/` corpus, every per-step `local_reward` is **integral** (`v == rint(v)`),
dtype `float32`. Integers are exact in float32 up to 2²⁴ = 16,777,216, and an episode total here is
≈ −3.3 × 10⁴ — six orders below. So the round-trip is exact and the sum reproduces in float64.

**Consequence for the design:** the gate asserts integrality explicitly before it asserts equality,
so that if the reward family ever stops being a count the gate fails *with the right diagnosis*
instead of looking like a transfer defect. If integrality ever fails, `==` is not achievable and
**that is a finding to report, never a tolerance to widen.**

```python
    return CellStats(n=count, mean=float(data.mean()), std=std,
```

⛔ **There is no resampling seed, because there is no resampling.** `mean_ci95` is the analytic
normal approximation `1.96·s/√n`: deterministic, no RNG, no `n_resamples`. `grep -rn "bootstrap"
offline/` returns only **TD bootstrapping** in the IQL value learner — a different word for a
different thing — and the single `default_rng` in `offline_baselines.py:3322` seeds *training-stream
selection*, not an interval.

**The brief presumes an estimator the repo does not have. The repo wins** (`CLAUDE.md` §2): P7.3a
uses `paired_comparison` → `mean_ci95`, reports `n`, mean, `ci95_low/high` and the Wilcoxon beside
it, and the packet states **"no resampling seed: the paired CI is analytic"** rather than inventing
one. Introducing a bootstrap would be a **new estimator**, which the same sentence forbids.
