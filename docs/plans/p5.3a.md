## 2. ⭐ What §6.1 would FAIL to detect (required by A12)

§6.1 re-rolls two committed `dt` cells through the changed code and asserts bit-exact per-episode
ATT. Stated plainly, here is what a green §6.1 does **not** license anyone to believe.

1. **It exercises one branch of the new field and never the others.** The path it runs is
   `from_checkpoint → load → DTConfig.from_json_obj(<8-key payload>) → "conditioned" → forward`.
   It never executes `to_json_obj` emitting the key, `from_json_obj` on a **9-key** payload,
   `__post_init__`'s rejection branch, the zeroing substitution itself, or
   `DTAgent.__init__(rtg_mode=…)`. Those live or die on §6.2 and the unit tests **only**.
2. **It is blind to any logit change that does not cross a decision boundary.** ATT is a function of
   the action sequence, which is a function of `argmax`. An edit that perturbed every logit and never
   flipped an action would leave ATT bit-identical and this test green. That is the *exact*
   flip-rate-versus-TVD distinction the probe exists to draw, and it applies to the guard as much as
   to the finding.
3. **It is, more weakly, blind to an action change that does not move horizon ATT.** Two different
   action sequences can in principle produce the same scalar. Unlikely at float64; not excluded.
4. **It covers 2 of the 40 committed `dt` cells.** Seeds 202–505 and the tiers `fixedtime`,
   `maxpressure`, `mappo500`, `mix33/50/67` are **not** re-rolled by it.
5. **It says nothing about the non-DT arms** (`bc`, `bc_top10`, `iql`), which never construct a
   `DTConfig`, nor about `SpatialDTAgent` (`SpatialDTConfig` is an independent dataclass,
   `agent/SpatialDTAgent.py:124`). Their protection is the full suite, not this test.
6. **It is a statement about this machine.** Bit-exactness is asserted on this GPU, this torch, this
   numpy. It is evidence about *the edit* only because the same harness reproduces the same column
   **without** the edit — which is why §4's Gate 0 exists and why the two mutations are mandatory.
7. **It cannot address training-time relevance at all.** A prompt can shape weights and then sit
   unused. That is P5.3b (brief §1's table), not this.

## 6. `offline/rtg_ablation.py` — `probe`

**Teacher-forced replay.** Logged states and logged actions are pushed through the model, so the
state sequence is **identical across interventions by construction** and any output difference is
attributable to the RTG alone.

- Windows are built with **`DTAgent`'s own `_window`** and a `_Context` advanced from the logged
  stream — the production inference layout (current action slot `PAD_ACTION`), not the loader's
  training layout. Normalisation goes through `DTAgent._normalise_state`, i.e. the checkpoint's own
  stats. Nothing is reimplemented.
- Baseline RTG is the inference-time construction: `target − cumulative logged reward`, then
  `/ rtg_scale` (`agent/DTAgent.py:596,662`), using the checkpoint's **own** recorded `target_rtg`.
- `avail_mask` is applied exactly as the model applies it, from the logged `avail` stream.

**Interventions — 12 configurations, fixed here, before any number:**

| key | intervention |
|---|---|
| `baseline` | the checkpoint's own `target_rtg` |
| `grid_g0 … grid_g8` | target replaced by each of `DECLARED_GRID`'s nine values |
| `zero` | RTG identically `0.0` in scaled units |
| `frozen` | RTG held at the target, never decremented |

⚠️ **`zero` is not `grid_g0`.** `grid_g0` sets the *target* to 0 and still decrements, giving
`−cumsum(r)`; `zero` feeds a constant 0. Confusing them would report the wrong quantity under the
right name.

**Reported per intervention, per (tier, seed):** `flip_rate` (headline), `tvd`,
`mean_abs_logit_delta` over legal actions, and `n_steps_compared`. **Never a bare pooled mean** —
per seed, plus the spread across the five (P5.1's lesson).

**Cell set (R3, R4):** 5 phase-1 tiers × 5 seeds; 20 streams per cell at indices `0,10,…,190` of the
declared 200-stream training set in `key` order. That stratifies across the five behaviour-seed
directories for the `mappo*` tiers instead of taking one directory's first 20. 20 × 360 = **7200
decision steps per cell**, so the flip-rate resolution is 1/7200 ≈ 0.014 %.
**Device: the default resolution** (`Utils.resolve_device(None)` → CUDA here), matching
`method_tier_grid`'s `--device` default, so the probe measures the numerics the reported column was
produced with.

## 8. `tables` — Gate 0's two tables

### Table 1 — return / RTG spread, all **8** hz1x1 tiers

Three rows, and **A6 is why they are three and not two**: §4.2 asked for agreement between two
quantities that are not the same quantity.

| row | quantity | population | estimator |
|---|---|---|---|
| **A** | per-episode return: `mean, sd, IQR, min, max` | the tier's **declared 200-stream training set** (`training_streams`) | — |
| **B** ⭐ | **between-episode sd of the RTG at `t ∈ {0, 90, 180, 270}`, and pooled** | the tier's **declared 200-stream training set** | — |
| **C** | `RtgSummary` `count/min/max/mean/std/quantiles`, **two routes** | the tier's **whole training split over `TierSpec.dirs`** — the population the loader fitted on | **`ddof=0`**, quantiles `RTG_QUANTILES`, `method="linear"` |

**Row C is the only cross-check.** Route 1 reads the committed `NormalizationStats` out of the
checkpoint payload (A5: **there is no other committed copy**, and the artifact says so). Route 2
recomputes it from the raw `.npz` reward arrays over **the same population and the same estimator**.
Rows A and B are separate rows and are **not** cross-checks of anything — asserting A against C would
fail for a correct implementation on `random` (144000 per-step values over 400 episodes against 200
streams) and on the mixtures.
**Row B is the quantity C4's hypothesis is about**: the model sees an RTG at *every* step, so
identifiability is about how much that value varies across episodes at a given point in the episode.
Every row is emitted in **raw and scaled** (`/ rtg_scale`) units, because scaled is what the network
receives.

### Table 2 — δ per tier: **measured, not a rule** (A7)

The δ **decision rule is withdrawn**. δ survives as a table and nothing more. Emitted per tier:
signed `mean_difference`, `ci95_low`, `ci95_high`, `ci95_half_width`, `wilcoxon`, `rank_biserial`,
`wins`/`losses`/`ties`, `n_shared_draws`, and the derived
**`behaviour_margin_degenerate = (ci95_low <= 0 <= ci95_high)`**.

Read from `behaviour_comparisons` in the committed `p4_6_grid.json` / `p4_7_grid.json`. Free checks,
already measured 2026-08-25 and asserted by the tests:

- `mappo1000` δ is `−0.6262756469347375`; **`round(abs(δ), 4) == 0.6263`** (A6's registered value —
  A7 leaves it untouched, the sign is stored negative and that is stated);
- **exactly 2 of 8 tiers are `behaviour_margin_degenerate`** — `fixedtime` and `maxpressure`;
- the five tiers present in both grids carry **bit-identical** δ in each, so reading either is safe
  and the tests read both;
- a tier absent from **both** grids raises, **naming the tier**.
