## 0. The defect, stated exactly

A1 pins the primary metric to **`average_travel_time` at the episode horizon** — the value of the
registered, survivorship-free per-step metric (`metrics/cityflow.py:234`) at the last decision step,
i.e. the mean over all vehicles that entered the network. `experiments/runner.py:168,175` instead
reports the **mean of the per-step samples** (a running mean). The two differ *policy-dependently*, so
every §3.1 anchor is a running mean of a running average and must be re-derived before it can anchor
any later phase.

**Naming ruling (obeyed everywhere I touch, incl. JSON keys / CSV headers / dataclass fields):**
- `att_horizon` — the registered primary metric (A1). The paper's "average travel time".
- `att_running_mean` — the legacy `runner.py` quantity. Never called "average travel time".
- No episode-level field/column/variable/dict-key is named bare `average_travel_time`. That bare name
  survives **only** as the registry metric string when *reading* it (`get("average_travel_time")`,
  `info["average_travel_time"]`, a `metric_names` list) — never as a key we construct.

**Verified grounding (read from source this session):**
- `envs/cityflow_env.py:269-272`: `info["average_travel_time"] = self._metrics.get("average_travel_time")`
  — present in every `info`. So `att_horizon` = `info["average_travel_time"]` at the final step.
- `metrics/base.py:214-215`: `update()` always runs `_run_step_hooks()`, so the depart/complete
  bookkeeping the metric needs is maintained regardless of the requested metric set.
- `experiments/runner.py:144-184` `evaluate_policy` is the loop to mirror: `eval_seed = seed+10_000`,
  baseline action RNG `seed+50_000+index`, `compare_with = ["random","max_pressure"]` (index 0/1).
- Only consumer of `ReplayResult.average_travel_time` is `tests/test_fixed_time_env_mapping.py`
  (grep-confirmed) — the rename is safe.

## 2. Deliverables

### D1 — `offline/horizon_metric.py` (the reader that locks the metric)
`horizon_rollout(env, choose_action, episodes, seed) -> HorizonRollout` (frozen dataclass), a
drop-in-signature mirror of `evaluate_policy`'s loop. Per episode it records the per-step
`info["average_travel_time"]` samples and reports **both** from one rollout:
- `att_horizon` = mean over episodes of `samples[-1]` (A1; per-episode last sample — Master-approved).
- `att_running_mean` = mean over episodes of `mean(samples)` (identical to `runner.py`).
Also exposes per-episode tuples, `episode_reward`, `final_vehicle_count`, and `final_completed`
(from `info["metrics"]["count_of_vehicles_completing_journey"]` when present, else `nan`) so Tier 1 can
derive `entered = final_completed + final_vehicle_count`. No key/field named bare `average_travel_time`.
