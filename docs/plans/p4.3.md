## 2. The calibration rule — declared in full, before any evaluation number

### 2.1 The quantity the rule is a function of

`R_i` = the **per-intersection episode return under the collection reward** of probe episode *i*:

```
R_i = Σ_{t=0}^{T-1} info_t["intersections"][ix]["reward"]      (T = max_steps = 360)
```

read from the post-step `info` of every step of a MaxPressure rollout, in the target domain, with the
env settings reconstructed from the corpus manifest (F7). This is the **same stream** the corpus
stores as `local_reward` (C6) and the same stream `DTAgent.act()` advances the RTG on (F6) — the rule
must be a function of the quantity the model is conditioned on, or it calibrates against a different
scale than it prompts with. With `global_reward_weight = 0.0` (F7) this carries no global component
(`PREREGISTRATION.md` §3.3, threat 5).

**Double-computed by an independent route** on hz1x1: the `queue_length` local reward equals
`-Σ_lanes lane_waiting_vehicle_count[t+1]` over the intersection's incoming lanes (`P2.4`'s exact
identity, registered as valid on hz1x1 and grid4x4). The probe runner recomputes `R_i` that way from
the same `info` dicts and **asserts exact equality**; a mismatch aborts the probe and writes nothing.

### 2.2 THE MECHANISM — Rule B, justified by FORM alone

> **Revised 2026-08-13 per `BRIEF_15` §12.1/§12.2.** The first version of this plan made **Rule A**
> primary, on the argument that `q = 1.0` transports the naive rule's functional. **That argument is
> wrong and the coordinator's counter is decisive: the functional is right and the distribution is
> not.** The naive target is the max of the **behaviour policy's** returns; a quantile of the
> **probe's** returns asks the DT to achieve *MaxPressure-level* return (`q = 1.00` → **−13112**,
> measured by the coordinator, 7,350 below the naive −5762). Rule A is therefore not the naive rule
> transported into a new domain — it is a different and worse rule. **It is demoted to a declared
> alternative with its failure predicted in advance (§2.4).**

```
RULE B, "probe-relative", the mechanism the paper names:

    target^target  =  R_best^source  ×  ( S(R^target_probe) / S(R^source_probe) )

    S       a declared probe statistic, reported both ways: S = max and S = mean
    R_best^source   the best achievable return in the SOURCE domain
                    = max training-split episode return = the naive target (F1)
    R^probe         per-intersection episode returns of a MaxPressure probe (§2.1),
                    measured in each domain
```

`rtg_scale` is **unchanged at the checkpoint's 9991.0** everywhere in this task (§2.5).

**Why this form, with both selectors withdrawn.** The rule must estimate *best-achievable* return in
the target domain, not *probe-achievable* return. Rule B does that by construction: it carries the
source domain's best-achievable level and rescales it by how much the target domain moves the return
scale, as measured by a policy that can be run in both. Rule A estimates the probe's own performance,
which is a policy we already know how to beat. **No evaluation number entered this choice**, and none
could have: the in-support criterion was withdrawn as a selector (§5) and ATT never was one.

**What this task can and cannot say about Rule B, stated before it runs.**
* **Cannot validate it.** In-domain, source and target coincide, so `S(R^target) = S(R^source)`, the
  ratio is exactly 1, and Rule B **returns the naive target identically**. It is a structural
  identity here, not a measurement. P7 is the task that exercises it.
* **Can assert the identity** rather than assert*ing* it in prose — a test, per §12.4 (T11).
* **Can measure the source-domain half of the ratio**, `R_best^source / S(R^source_probe)`, which P7
  needs and which is measurable only here. Reported for **S = max and S = mean**, at each `k`.
* **Rule B's in-domain point costs no rollouts**: it *is* the naive grid point `−5762`, so its ATT is
  the Gate A cell (§4). That equality is a consequence to state, not a coincidence to discover.

**Determinism (T4).** Both rules are pure functions of probe returns (plus, for Rule B, the corpus's
`R_best^source`). Neither reads a held-out draw, an ATT, the gate artifact or a grid result.

### 2.3 The source-domain ratio — the deliverable P7 consumes

```
ratio_S(k)  =  R_best^source / S( {R_i : i ∈ 201 … 200+k} )        for S ∈ {max, mean}, k ∈ {5, 20, 100}
```

Six numbers, no rollouts beyond the probe. `R_best^source = −5762.0` is read from the checkpoints and
cross-checked against `p4_training.json` (F1), never restated. Both statistics are reported because
they answer different questions — `max` is what the naive rule's functional would use and is
sample-size sensitive by construction; `mean` is stable in `k` and is the one a small probe budget can
estimate. **Neither is selected here**; P7 declares which it uses before it runs.

### 2.4 Rule A — a declared alternative, PREDICTED NOW to be poor

```
RULE A, "probe-quantile":   target  =  Q_q( {R_i : i ∈ probe draws} ),  numpy quantile, method="linear"
                            evaluated at q = 1.00, k = 100
```

**Registered prediction, written before the rollouts and scored afterwards (`BRIEF_15` §12.2 item 4):
Rule A lands materially worse than the naive target on ATT, and the reason is that it targets probe
performance rather than best-achievable performance.** Running it and reporting the failure is the
evidence that the mechanism must be *relative*; quietly not running it would leave that as an
assertion. It gets **one** evaluated point (`k = 100`), for the reason §12.6 gives about the secondary
quantiles: the grid already spans the target space, so nearby variants re-measure it.

`q ∈ {0.50, 0.75, 0.90}` and `k ∈ {5, 20}`: **target values only, located on the grid, never rolled
out** (§12.6). A table nobody may select from is temptation with a provenance.

### 2.5 `rtg_scale` does not vary

`rtg_scale = 9991.0` for **every** grid point, every rule point and every seed, equal to the value in
each checkpoint. It is the normalisation divisor, not a prompt. Asserted per point in the artifact and
guarded by T5.

## 5. The two criteria — and **neither** of them selects

> **Revised 2026-08-13 per `BRIEF_15` §12.1: the in-support selector is WITHDRAWN.** The measurement
> that killed it is in this plan's own §5 prediction 1, made before any rollout: `target = 0` is
> in-support **0.000** while being the best point anyone has measured (n = 1, P4's review). A
> criterion that would reject the apparently best point is not a weak proxy — on this evidence it
> points the wrong way. The confusion it rested on is **reliability** (out-of-support inputs make
> behaviour unpredictable — true) mistaken for **performance** (in-support targets do better — does
> not follow). For a return-conditioned model it is close to backwards: conditioning on an
> optimistic and therefore extreme return **is** the mechanism.

| criterion | definition | may it select? |
|---|---|---|
| **in-support fraction** | of the `T = 360` decisions in an episode, the fraction whose RTG input lies in the **closed** interval `[-9991.0, -6.0]` (F2) | **NO — withdrawn as a selector (§12.1).** Reported for every point as a **reliability diagnostic and caveat generator**: it says how far outside its training support a point drives the model, which is what a limitation section needs and is not a performance claim |
| **ATT at the horizon** | `att_horizon`, A1's primary metric, over 5 seeds × 100 held-out draws | **NO. It scores every point and chooses none.** No target reported by this task is chosen because it scored well |

**With both selectors gone, what makes the rule non-arbitrary is its FORM** (§2.2), and the only form
that qualifies is Rule B. This is the honest position and it is weaker than the one the brief opened
with — which is why it is written down here, before the numbers, rather than discovered afterwards.

**Exact definition, so the boundary cannot drift (T3).**

```
rtg_t   = target_rtg - Σ_{s<t} r_s              (unscaled; F6, recorded via agent.current_rtg())
in_support(t)  ⇔  RTG_MIN ≤ rtg_t ≤ RTG_MAX     with RTG_MIN = -9991.0, RTG_MAX = -6.0
below(t)       ⇔  rtg_t < RTG_MIN
above(t)       ⇔  rtg_t > RTG_MAX
```

Both ends **inclusive**; `below` and `above` are strict, so the three counts partition the 360
decisions exactly and the artifact asserts `in + below + above == n_decisions` per episode. The
scaled input `rtg_t / 9991.0` gives the identical verdict because the divisor is positive, and the
range is stated **unscaled** because that is the form the training statistics are recorded in.
`RTG_MIN` and `RTG_MAX` are read **from each checkpoint's own frozen stats**, not restated as
literals; the values above are what that read returns today (F2), and a checkpoint that disagrees
aborts the run.

Reported for every evaluated point: mean in-support fraction, the below/above split (they mean
opposite things — `above` is "prompted for a return better than anything in training", `below` is
"prompted for a return worse than anything in training"), and the per-episode counts.

**Registered predictions, scored and never used to select** (they exist so a favourable outcome
cannot be assembled afterwards; sources: F2, and P4's review MINOR-1/MINOR-2 at n = 1):

1. `target = 0.0` → in-support fraction **exactly 0.000** (rtg starts at 0 > −6 and is non-decreasing).
2. `target = -5762.0` → in-support fraction in **[0.70, 0.85]** (review measured 75/360 = 20.8 % *positive*; the −6 boundary makes the out-of-support share slightly larger).
3. My probe's `max` return over draws 201–300 lands in **[−14000, −12000]**, hence **below −9991**, hence Rule A's target is outside the training support. ⚠️ **This is an informed prediction, not a blind one, and the difference is disclosed:** the coordinator measured `−13112` on their own draw set (`BRIEF_15` §12.1) before I ran anything. My probe uses draws 201–300 and will produce its own number.
4. **Rule A's ATT is materially worse than the naive target's** — the registered prediction `BRIEF_15` §12.2 item 4 asks for, with the reason stated in advance: it targets probe-achievable rather than best-achievable return.
5. The ATT-optimal grid point is at or near `0`, i.e. **the reliability diagnostic and the outcome disagree** — the very disagreement that withdrew the selector, now measured at n = 500 per point instead of n = 1.
6. *Structural, asserted rather than predicted (T11):* Rule B's in-domain target equals the naive target **exactly**, so its ATT is Gate A's cell.

If 3 and 4 hold, the honest reading is the one the brief licenses in §12.2: *the mechanism cannot be
validated in-domain; a rule that calibrates on a weak probe's own level is poor here, and that is the
evidence that the mechanism must be relative.* Reported as such — not as a defeat, not as a success.
