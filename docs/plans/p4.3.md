## 2. The calibration rule — declared in full, before any evaluation number

### 2.1 The quantity the rule is a function of

`R_i` = the **per-intersection episode return under the collection reward** of probe episode *i*:

```
R_i = Σ_{t=0}^{T-1} info_t["intersections"][ix]["reward"]      (T = max_steps = 360)
```

read from the post-step `info` of every step of a MaxPressure rollout, in the target domain, with the
env settings reconstructed from the corpus manifest (F7). This is the **same stream** the corpus
stores as `local_reward` (C6) and the same stream `DTAgent.act()` advances the RTG on (F6) — the rule
must be a function of the quantity the model is conditioned on, or it calibrates against a different
scale than it prompts with. With `global_reward_weight = 0.0` (F7) this carries no global component
(`PREREGISTRATION.md` §3.3, threat 5).

**Double-computed by an independent route** on hz1x1: the `queue_length` local reward equals
`-Σ_lanes lane_waiting_vehicle_count[t+1]` over the intersection's incoming lanes (`P2.4`'s exact
identity, registered as valid on hz1x1 and grid4x4). The probe runner recomputes `R_i` that way from
the same `info` dicts and **asserts exact equality**; a mismatch aborts the probe and writes nothing.

### 2.2 THE RULE

```
                                    ┌
target_rtg  =  Q_q( { R_i : i ∈ probe draws } ),   Q = numpy quantile, method="linear"
                                    └
PRIMARY, declared now:   q = 1.00        k = 100        probe draws 201 … 300
```

with `rtg_scale` **unchanged at the checkpoint's 9991.0** for every point in this task (§2.5).

**Why `q = 1.0`, decided with no evaluation number in existence and defended by form, not by score.**
The naive rule P4 reported is *the maximum of the behaviour corpus's episode-return distribution*.
The calibrated rule is **the same functional applied to a different distribution** — the probe's,
measured in the target domain. Holding the functional fixed and changing only *whose returns are
measured* is what makes the naive/calibrated contrast a test of the probe rather than a test of two
unrelated heuristics. A lower quantile would target the *typical* probe episode, which is a different
mechanism and would confound the comparison. **No scale factor is applied** (DTLight's
`max_offline_return × scale` already owns within-domain scaling, `PREREGISTRATION.md` §10, and a
sweepable multiplier is precisely the free parameter A8(a) forbids us to fit).

**Why `k = 100`:** it is the largest budget C3 registers, and more probe episodes are strictly more
information; `k ∈ {5, 20}` are reported as the budget ablation (§3.3), never as candidates to choose
from by ATT.

**Determinism of the rule (T4).** `target_rtg` is a pure function of the probe returns. It reads no
held-out draw, no evaluation ATT, no gate artifact and no grid result. Same probe input ⇒ same target.

### 2.3 The rule form this task CANNOT test, named so the paper does not overclaim

A second form is natural for the cross-domain case and is **not** evaluated here:

```
target_rtg  =  τ_naive^source × [ Q_q(R^target) / Q_q(R^source) ]          (RULE B, "probe-relative")
```

In-domain, source and target coincide, so the ratio is **1 by construction** and Rule B returns the
naive target identically — it is a structural identity here, not a measurement. Evaluating it in
domain would produce a number that looks like a result and contains none. It is recorded here as the
candidate P7.2 must test, where the ratio is a measured quantity. **The brief's honesty note (§3) is
therefore sharpened:** "any correct rule must approximately reproduce the naive target in-domain" is
true of **Rule B** and **false of Rule A**, because the probe policy (MaxPressure) is not the
behaviour policy (MAPPO@1000) and its return distribution is not the corpus's. This task tests Rule A.

### 2.4 Rule-form ablation, reported as target VALUES only

`q ∈ {0.50, 0.75, 0.90, 1.00} × k ∈ {5, 20, 100}` — twelve targets, computed from the same probe
episodes at zero extra cost and reported in `p4_3_probe.json`. **Only `q = 1.0` gets rollouts**
(§3.3). The others carry no ATT and no in-support fraction, because both require rollouts; reporting
a target value without pretending to know its outcome is the honest form.

### 2.5 `rtg_scale` does not vary

`rtg_scale = 9991.0` for **every** grid point, every rule point and every seed, equal to the value in
each checkpoint. It is the normalisation divisor, not a prompt. Asserted per point in the artifact and
guarded by T5.

## 5. The two criteria — and the one that may select

| criterion | definition | may it select? |
|---|---|---|
| **in-support fraction** | of the `T = 360` decisions in an episode, the fraction whose RTG input lies in the **closed** interval `[-9991.0, -6.0]` (F2) | **YES.** It reads no evaluation return: it is a function of the conditioning trajectory alone, and a prompt that keeps the model inside the support it was trained on is better *by construction* |
| **ATT at the horizon** | `att_horizon`, A1's primary metric, over 5 seeds × 100 held-out draws | **NO. It scores every point and chooses none.** No target reported by this task is chosen because it scored well |

**Exact definition, so the boundary cannot drift (T3).**

```
rtg_t   = target_rtg - Σ_{s<t} r_s              (unscaled; F6, recorded via agent.current_rtg())
in_support(t)  ⇔  RTG_MIN ≤ rtg_t ≤ RTG_MAX     with RTG_MIN = -9991.0, RTG_MAX = -6.0
below(t)       ⇔  rtg_t < RTG_MIN
above(t)       ⇔  rtg_t > RTG_MAX
```

Both ends **inclusive**; `below` and `above` are strict, so the three counts partition the 360
decisions exactly and the artifact asserts `in + below + above == n_decisions` per episode. The
scaled input `rtg_t / 9991.0` gives the identical verdict because the divisor is positive, and the
range is stated **unscaled** because that is the form the training statistics are recorded in.
`RTG_MIN` and `RTG_MAX` are read **from each checkpoint's own frozen stats**, not restated as
literals; the values above are what that read returns today (F2), and a checkpoint that disagrees
aborts the run.

Reported for every evaluated point: mean in-support fraction, the below/above split (they mean
opposite things — `above` is "prompted for a return better than anything in training", `below` is
"prompted for a return worse than anything in training"), and the per-episode counts.

**Registered predictions, scored and never used to select** (they exist so a favourable outcome
cannot be assembled afterwards; sources: F2, and P4's review MINOR-1/MINOR-2 at n = 1):

1. `target = 0.0` → in-support fraction **exactly 0.000** (rtg starts at 0 > −6 and is non-decreasing).
2. `target = -5762.0` → in-support fraction in **[0.70, 0.85]** (review measured 75/360 = 20.8 % *positive*; the −6 boundary makes the out-of-support share slightly larger).
3. The probe's maximum return is **below −9991**, i.e. the calibrated target lands **outside** the training support (MaxPressure's ATT is 176.89 against the behaviour policy's 105.58).
4. ATT at the calibrated target is **worse** than at the naive target (the probe is the weaker policy).
5. The in-support-optimal target and the ATT-optimal target are **different points**, and the ATT-optimal one is at or near 0 — i.e. the leakage-free criterion and the outcome criterion disagree.

If 3 and 4 hold, the honest reading is the one the brief already licenses: *in-domain, a rule that
calibrates on a weak probe is a poor rule, and the mechanism's value is confined to the cross-domain
case P7 tests* — reported as such, not as a defeat and not as a success.
