## 4. Item 2 — CI

### 4.1 Files

```
.github/workflows/ci.yml       one workflow, on push + pull_request
.github/ci/ci_gate.py          the gates, as a CLI: pytest-gate | guard-gate | wheel-gate
.github/ci/ci_baseline.json    the declared skip ceiling + the known guard baseline
```

`.github/` is **not** in `claude_guard.sh`'s `FROZEN_PATTERNS` (verified by reading the variable) and
`scripts/` is untouched. The gate logic lives in a Python file rather than in YAML **so that it can be
tested and shown to go red locally**, which is the only kind of proof available to me (§1).

### 4.2 Job layout (single job, `ubuntu-latest`)

1. checkout · `setup-python 3.12` with pip cache · `pip install -e ".[dev]"`.
2. **Suite**, pinned: `OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 pytest -q -rs --junit-xml=…` teed to a
   file. `DEFERRED` 41 is the reason for the pin and the workflow says so in a comment.
3. **`pytest-gate`** (`if: always()`): parses the run **twice, independently** — the terminal tail
   *and* the JUnit XML — and **fails if the two disagree**. This is the C2 "compute critical
   quantities twice" rule applied to the one number nobody reads. Then: fail if `failed+errors > 0`;
   fail if `skipped > skip_ceiling`; always echo `passed/skipped/failed` and write them plus the
   full `-rs` skip-reason block to `$GITHUB_STEP_SUMMARY`, so **the counts are part of the result**.
4. **Three guards**, each with **no arguments**, output captured, `|| true` so the gate — not the
   guard's exit code — decides:
   * `bash scripts/claude_guard.sh --frozen-only` — expected exit 0. ⚠️ **On a clean checkout this
     check is vacuous** (it reads `git status`, which is clean in CI). The workflow says so in a
     comment rather than letting a green tick imply more than it proves. A PR-diff variant is §7 Q2.
   * `bash scripts/check_english.sh` → `guard-gate --name english`
   * `bash scripts/check_test_hygiene.sh` → `guard-gate --name hygiene`
5. **`wheel-gate`**: `pip wheel . --no-deps` → assert every top-level package is in the wheel. This is
   item 1's **regression** protection; without it, `offline*` can be dropped again silently.

### 4.3 The guard baseline

Baseline is a map `file → {rule → count}` — **not** a total and **not** file:line (line numbers move
under any edit; a total lets a fix in one file pay for a new violation in another). `english` findings
carry the synthetic rule id `PL`. Recorded values are M7 and M8 exactly.

**Verdict:** any `observed[file][rule] > baseline[file][rule]` (missing baseline entry = 0) → **exit 1,
naming file, rule, baseline and observed**. Fewer findings → exit 0 plus a `NOTE: the baseline can be
tightened` line in the summary. Guards are never edited and never made green; the 16 and the 5 stay.

### 4.4 The skip ceiling — the part I must be most careful about

The workflow does **not** build CityFlow (ruled, §0a Q4), so the declared ceiling is M9's condition:

```
skip_ceiling = 62      provisional = true
```

**The ceiling is 62 BECAUSE CityFlow is not built.** Building it would move it to **31** (M10). That
sentence goes in the baseline file itself, not only here: the number is a consequence of a choice and
a future reader must be able to see the lever.

**Mandated expiry, recorded in the file (§0a):** P5.1's merge adds ≈24–25 skips (it measured
**984 / 53** corpus-absent in its own tree against **898 / 28** for the same condition on `main`), so
the baseline carries `re_measure_required_at` naming that merge, its reason and its authority. A
`tests/test_ci_gate.py` case asserts those fields are present and non-empty, and the gate echoes the
expiry note into **every** job summary — so the expiry cannot live only in a chat.

62 = 31 corpus/checkpoint-gated + 29 (+2 class-level) cityflow-gated + 10 SUMO-gated + 2 matplotlib
+ 1 unmaterialised probe draw, from M9's `-rs` block, which is committed verbatim beside the number.

**Provenance is recorded in the file itself**: measured on the dev machine under a simulated runner
(`cityflow` and `matplotlib` unimportable via a `ModuleNotFoundError`-faithful blocker, `sumo` removed
from `PATH` via a symlink farm, `SUMO_HOME` and all `RLTRAFFIC_*` unset, threads pinned, CUDA hidden),
**never on a GitHub runner**. If the real runner skips more, **the job goes red and prints the
observed number and the exact file to update** — which is the correct behaviour for a ceiling nobody
has yet observed, and strictly better than padding it with slack that would blind the gate.

*Why not build CityFlow in CI (which would put the ceiling at M10's 31 and run 31 more tests):* I
cannot verify that the vendored C++ tree builds on `ubuntu-latest` (M15), and shipping an unverified
3-minute build step whose failure mode is a red main branch is a worse trade than declaring the 31
skips. Recommended as a follow-up in §7 Q4.

### 4.5 Tests — `tests/test_ci_gate.py`

Every test invokes the **real** `.github/ci/ci_gate.py` as a subprocess (the style of
`tests/test_claude_guard.py`, which tests the real script rather than a reimplementation).

| test | proves |
|---|---|
| tail and JUnit agree → exit 0 | the happy path |
| tail says 3 skipped, JUnit says 30 → **exit 1** | the double-compute is load-bearing, not decoration |
| `skipped == ceiling` → 0; `skipped == ceiling + 1` → **exit 1** naming the ceiling | requirement §3.1(3) |
| `failed = 1` → **exit 1** even under the ceiling | the gate cannot certify a red suite |
| unparseable tail → **exit 1** | a parser that silently returns 0 is the "badge that cannot go red" |
| guard baseline: identical → 0 · one extra finding in a known file → **1** · a finding in an unknown file → **1** · fewer findings → 0 with `NOTE` | requirement §3 |
| wheel without `offline/` → **exit 1**; the repo's real wheel → 0 | item 1's regression cover |
| the workflow file pins `OMP_NUM_THREADS`/`MKL_NUM_THREADS`, passes `-rs`, and invokes all three guards and both gates | textual only, and labelled as such — it catches deletion, not semantics |
