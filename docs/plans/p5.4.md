## 0. THE GATE'S LOAD-BEARING ITEM — one finding that makes A22(b) fire on a correct model

### F1 — A22(b)'s exact-zero support check is an identity for ONE spatial layer; the registered checkpoints have THREE

**This blocks the code phase.** I will not implement either reading of the support check until a ruling lands on
`main`. A22(b) is a registered clause, so changing it is not mine to decide (channel (b)). Implementing it literally
produces a false channel-(c) alarm (below).

**What A22(b) says** (verbatim, `PREREGISTRATION.md:380`): *"For every spatial checkpoint F[i, j] must be **exactly 0**
wherever the recorded mask is False (non-neighbours) … The hard −∞ attention bias makes this an identity, so a violation
is a defect in the mask's application to trained models."* The brief's §3 restates it the same way.

**What the architecture does.** The code, not a docstring:
- `SpatialDecisionTransformer.forward` (`agent/SpatialDTAgent.py:391-392`) applies the **same** one-hop `spatial_bias`
  in **every** block: `for block in self.blocks: hidden = block(hidden, temporal_bias, spatial_bias)`.
- Every one of the ten payloads carries `config.n_layer = 3` (*measured*).
- Layer 1's spatial sublayer puts node *j*'s information into its neighbour *k*'s token. Layer 2's temporal sublayer
  carries it along *k*'s sequence. Layer 2's spatial sublayer hands it to *k*'s neighbour *i*.
- So node *i*'s last-step logits depend on **every node within `n_layer` hops**, not only on its mask neighbours. That is
  the ordinary receptive field of a stacked graph-attention network. The −∞ bias makes the **per-layer** attention
  one-hop, and nothing more.

**Measured, not argued** (Appendix A: random-init `SpatialDecisionTransformer`, eval mode, node *j*'s K-step state block
replaced by another window's, `torch.equal` on node *i*'s last-step logits):

```
path 0-1-2-3, n_layer=1: support==mask True,  support==reach^1 True
path 0-1-2-3, n_layer=2: support==mask False, support==reach^2 True
path 0-1-2-3, n_layer=3: support==mask False, support==reach^3 True
grid4x4 mask, n_layer=3, d_model=128, n_head=4 (random init):
  non-neighbour pairs (mask False): 192
  of which changed (would be 'violations' under the one-hop reading): 132
  support == reach^3: True  reach^3 off-diag True: 180  pairs beyond 3 hops: 60  changed beyond 3 hops: 0
```

The lattice's ordered pairs by hop distance (BFS on the recorded mask, *measured*):
`{1: 48, 2: 68, 3: 64, 4: 40, 5: 16, 6: 4}`. The 132 pairs are exactly the 2- and 3-hop ones (68 + 64). The 60 pairs at
≥ 4 hops are exactly zero.

**Why nothing caught it.** The random-init tests the brief cites (`tests/test_spatial_dt_agent.py:321-360`) use a 3-node
stub where the non-neighbour (node 2) is **isolated**. No 2-hop path exists there, so `reach^L == mask` for every L, and
the tests cannot tell the two readings apart. The brief's T1 uses the same stub, so as written it cannot either.

**Consequences if implemented as registered.**
1. On all five `dt_spatial_h4` checkpoints the check would report violations on 2- and 3-hop pairs of a correctly
   working model. It would refuse the artifact and send a channel-(c) *"defect in the mask's application"* — a false one.
2. The `nomix` half of A22(b) is correct as written: the identity mask has `I^L = I`, so off-diagonal exactly 0 is an
   identity at any depth.

**Proposed ruling (for the coordinator; I have not implemented it):**
- **(R1)** The spatial exact-zero check becomes: `F[i, j] == 0` exactly (compared as `torch.equal` on the raw per-window
  logits) wherever **`(M^L)[i, j]` is False**.
  - M is the recorded mask, self-loops included, taken as a boolean matrix power.
  - L is the payload's `config.n_layer` (3).
  - On grid4x4 that is the **60** ordered pairs at hop distance ≥ 4. The `nomix` clause is unchanged.
  - This is still a defect test with the same power: a mask not applied, or applied to the wrong rows, would leak into
    those pairs.
- **(R2)** T1 is strengthened with a case that can see the difference:
  - A 4-node path graph at `n_layer = 2`, where the support must equal `reach^2` exactly.
  - Mutation M1b: the check uses the one-hop mask instead of `reach^L`. On a correct model it reports violations, so it
    dies.
  - The brief's 3-node stub case and its all-True-mask mutation stay as written.
- **(R3)** A22(c)'s r is **unchanged**: one-hop neighbours, as registered and as the brief's T2 mutation presumes.
  - Two things I flag without deciding: (i) r does not count 2–3-hop influence; (ii) the TRIVIAL clause's *"the trained
    models did not mix"* is then a statement about one-hop influence.
  - F itself goes into the artifact whole, so the 2–3-hop entries are on disk for anyone to read. I will not add a
    statistic over them unless you rule one in.
- **(R4)**, information for the paper and not a defect: any prose saying the model *"attends to its neighbours"* is
  per-layer true, but its **effective** receptive field is 3 hops.

## 2. The protocol, restated from the code (what G0 checks)

### 2.1 Windows
- **Dataset.** `TrajectoryWindowDataset(<the five dirs of tier_sweep.TIERS["mappo1000"]>, context_length=K,
  split="train", normalize=False)`. K = the payloads' `config.context_length` (20 for all ten). The run refuses if the
  ten disagree, because the matched design needs one window set.
  - `normalize=False` is deliberate: raw rows come out, and normalisation is applied by `act`'s own route (§2.4).
  - `split="train"` is the mechanism that keeps a held-out draw out (`dataset.py:561-565`), exactly as the trainers
    built it (`tier_sweep.tier_dataset`, `:1429-1442`).
- **Window content.** A window is `dataset[item]`: the K steps ending at decision `t`, rows `max(0, t-K+1) … t`,
  left-padded (`dataset.py:787-811`).
  - `rtg` is the raw suffix sum inclusive of `r_t`.
  - `action` pads with `PAD_ACTION = -1`.
  - `timestep` is absolute.
- **Joint instants.** `build_joint_index(dataset, node_ids)` groups items by `(episode_index, t)` read from
  `item_meta`, never from index arithmetic (`joint_windows.py:135-141`). Rows are sorted by that key (`:172`).
- **Tensors.** `stack_joint(dataset, index)` gives the flat tensors built from `__getitem__` plus
  `member_index[m, n]` (`joint_windows.py:186-217`). The sample is the flat tensors gathered at
  `member_index[chosen_rows]`, shape `(200, 16, K, …)`, in the payload's node order. That order equals the corpus
  order by V3 and is re-checked at run time.
- **Eligible instants (D2, needs a ruling).** Joint rows with `t ≥ K−1`: full windows, no left padding. That is
  68,200 of 72,000 (341 of 360 per episode).
- **The declared seed: `20_260_919`** (one integer, today's date). One `np.random.default_rng(20_260_919)` drives, in
  this order:
  1. `chosen_rows = rng.choice(eligible_rows, size=200, replace=False)`, where `eligible_rows` is the ascending array
     of eligible joint rows. Window position m is the m-th value returned, unsorted.
  2. `sigma = rng.permutation(200)`, then `donor[sigma[k]] = sigma[(k + 1) % 200]`. That is one random cyclic
     derangement: every window gives and receives exactly once, and **no window is its own donor**, by construction
     rather than by rejection.
- **Recorded per window, so G1 can recompute by its own route:** dataset directory name, episode file, flow draw, `t`,
  `donor`, and the count of pairs whose donor lies in the same episode (descriptive only).

### 2.2 Perturbation (A22(a) — not a choice)
- For node *j* in window *m*, replace node *j*'s **whole K-step state block** with node *j*'s block from window
  `donor[m]`. RTG, actions, timesteps, attention mask, avail mask and every other node stay untouched.
- The donor block is already normalised with **node *j*'s own** statistics, because it is the same node. Swapping
  normalised blocks therefore equals normalising swapped raw blocks, since normalisation is row-wise and elementwise.
- `j = i` gives F[i, i].
- One pairing serves all 16 *j* and all ten checkpoints (matched).

### 2.3 Readout and F (A22(a) — not a choice, with one definitional detail)
- `logits = model(rtg_scaled, state, action, timestep, spatial_mask, attention_mask, avail_mask)[:, :, -1, :]`: node
  *i*'s **last-step** `masked_action_logits` as the model emits them (`SpatialDTAgent.py:400`), before any argmax.
  - The model runs in **eval mode under `torch.no_grad()`, on CPU**, exactly as `act` sets it (`:763-777`). Dropout
    (0.1 in these configs) is off.
  - `spatial_mask` is the **recorded** one (`agent.spatial_mask`, adopted from the payload by `load`, `:892-902`).
- Base and perturbed forwards run on the same `(200, 16, K, …)` shapes, one forward per *j* plus one base per
  checkpoint.
- **F[i, j]** = mean over the 200 windows of [mean over the **legal** last-step actions of
  `|logit'_{m,i,a} − logit_{m,i,a}|`], computed in float64 from the float32 logits.
  - **D3:** illegal actions are `−∞` in the emitted logits (`DTAgent.py:209-211`), and `−∞ − (−∞)` is NaN, so the mean
    runs over the legal entries.
  - **On this corpus the choice is moot:** all 8 actions are legal at every last step (V7). The artifact records the
    measured legal count, so that is visible rather than asserted.
- **Support check** (A22(b), form pending F1):
  - For every *j* and every *i*, `unchanged[i, j] = torch.equal(perturbed_j[:, i], base[:, i])` over all 200 windows
    and all actions: raw per-window logits, never a mean.
  - A violation is any pair in the must-be-zero set with `unchanged` False.
  - The must-be-zero set is `~(M^L)` under R1, or `~M` as registered. Nomix: off-diagonal, either way.
- **No NaN / non-finite F is ever written.** A non-finite entry refuses the artifact.

### 2.4 How `act`'s normalisation is reused (brief §3: "read it; do not re-derive")
- Each checkpoint is loaded with **`SpatialDTAgent.from_checkpoint(node_order, path, device="cpu")`**.
  - `node_order` is a minimal object exposing `.intersections` (ids from the corpus order, `num_phases = 8`) and
    `action_space = None`. `Utils.infer_action_counts` then falls back to `num_phases` (`agent/utils/utils.py:29`).
  - That makes the agent's own `load` (`:854-913`) run every one of its refusals: format version, `n_actions`,
    `n_nodes`, the intersection order, normalise-without-stats, and a missing mask.
- Every real state row of node *i* is normalised with **`agent._normalise_state(ix_id, row)`**. That is the method
  `act` calls at `:748`, which applies `payload.stats.normalize_state(payload.scenario_id, ix_id, row)` iff
  `payload.normalise` (`:648-654`).
  - Calling the private helper is deliberate. It follows the convention `offline/spatial_mixing.py`'s docstring
    records: *importing them — including the private helpers — is deliberate … a second implementation of the same
    protocol is exactly how two arms stop being comparable.*
- **Double computation (refusal if unequal).** The same block is also normalised by the dataset's route,
  `NormalizationStats.from_json_obj(payload["stats"]).normalize_state(scenario_id, ix_id, block)`, which is the call at
  `dataset.py:795`. The two must be `torch.equal`.
  - Both are IEEE float32 elementwise `(x − mean) / std`, so they must agree bit for bit.
  - V5 already shows the statistics equal the corpus-fitted ones the trainer normalised with.
- **RTG (D4).** The window's raw RTG is divided by the payload's per-node `rtg_scale` as a float32 tensor. That is the
  division the trainers fed these models (`tier_sweep.py:867-884`, `stacked["rtg"][selected] / scale`).
  - `act`'s `np.float32(value / scale)` (`:687`) can differ from it in a last bit (double rounding).
  - The RTG is identical in the base and perturbed forwards, so it cannot touch the support check.

### 2.5 The statistic, threshold and verdict (A22(c) — not a choice)
- `r_seed = mean_i( mean_{j ∈ N(i)} F[i, j] ) / mean_i F[i, i]` in float64.
  - N(i) = the **one-hop neighbours without self**: `adjacency.undirected[i]` from `offline/roadnet_graph.py` via
    `tier_sweep.adjacency_for_tier`, the trainers' own graph.
  - It equals the spatial payloads' recorded mask minus its diagonal (V4). The run re-checks this and refuses a
    mismatch.
  - For `nomix`, whose recorded mask has no off-diagonal entry, N(i) is the **same lattice**. Its r must then be exactly
    `0.0`, as the brief's control requires, and the writer refuses otherwise.
- If `mean_i F[i, i] == 0`, r is undefined and the run **refuses**. I have no evidence this occurs; stated so the
  division has a declared behaviour.
- `median` = `statistics.median` of the five spatial r's, which for n = 5 is the middle value exactly.
- **Verdict `TRIVIAL` iff median < 0.10, else `NON-TRIVIAL`.** The boundary 0.10 itself is `NON-TRIVIAL`.
- The ATT column is descriptive and untested: per seed, `np.mean` of `att_horizon` over that seed's episodes in file
  order, read through `tier_sweep.episodes_of_seed`. That refuses a duplicate draw and is P5.x's per-seed-mean
  convention (`spatial_mixing.per_seed_advantages:522`).
  - Each value is checked to round to A22(c)'s two-decimal figure.
  - The five-seed sample sd (ddof 1) is recorded.
  - **No correlation or other statistic between r and ATT is computed.** A22 registers the relation as descriptive only.

## Appendix A — the multi-hop probe (random-init; the only trained-payload field read is the mask)

```python
import numpy as np, torch
from agent.SpatialDTAgent import SpatialDecisionTransformer, SpatialDTConfig

def reach(mask, hops):
    m = mask.astype(np.int64); out = np.eye(len(mask), dtype=np.int64)
    for _ in range(hops): out = ((out @ m) > 0).astype(np.int64)
    return out.astype(bool)

def changed_support(mask, n_layer, d_model=16, n_head=1, K=4, D=4, A=3, B=5, seed=0):
    N = mask.shape[0]
    torch.manual_seed(seed)
    model = SpatialDecisionTransformer(SpatialDTConfig(state_dim=D, n_actions=A, n_nodes=N, context_length=K,
        n_layer=n_layer, n_head=n_head, d_model=d_model, dropout=0.0, max_ep_len=360)).eval()
    g = torch.Generator().manual_seed(1)
    rtg = torch.randn(B, N, K, 1, generator=g); st = torch.randn(B, N, K, D, generator=g)
    act = torch.randint(0, A, (B, N, K), generator=g); ts = torch.arange(K).view(1,1,K).expand(B,N,K).contiguous()
    am = torch.ones(B, N, K, dtype=torch.bool); mk = torch.from_numpy(mask)
    with torch.no_grad():
        base = model(rtg, st, act, ts, mk, am, None)[:, :, -1]
        sup = np.zeros((N, N), dtype=bool)
        for j in range(N):
            s2 = st.clone(); s2[:, j] = st.roll(1, dims=0)[:, j]   # node j's block from another window
            out = model(rtg, s2, act, ts, mk, am, None)[:, :, -1]
            for i in range(N):
                sup[i, j] = not torch.equal(out[:, i], base[:, i])
    return sup

path = np.eye(4, dtype=bool)
for a, b in ((0,1),(1,2),(2,3)): path[a,b] = path[b,a] = True
for L in (1, 2, 3):
    s = changed_support(path, L)
    print(f"path 0-1-2-3, n_layer={L}: support==mask {np.array_equal(s, path)}, support==reach^{L} {np.array_equal(s, reach(path, L))}")

p = torch.load("<main tree>/output/p5_2/checkpoints/grid4x4_mappo1000_dt_spatial_h4_seed101.pt",
               map_location="cpu", weights_only=False)
grid = np.asarray(p["spatial_mask"], dtype=bool)   # the MASK only; weights are NOT loaded into the model
s = changed_support(grid, 3, d_model=128, n_head=4, K=20, D=40, A=8, B=4)
# -> 192 non-neighbour pairs, 132 changed, support == reach^3, 60 beyond 3 hops, 0 changed beyond 3 hops
```
