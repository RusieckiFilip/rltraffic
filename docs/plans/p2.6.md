### 0.1 ✅ `info["average_travel_time"]` is invariant to the requested metric set

The brief's entire escape hatch. Measured by rolling out the *same* scenario/seed/policy twice —
once with the corpus's 1-metric set, once with a 3-metric set including `average_travel_time` and
`count_of_vehicles_completing_journey` — and comparing the per-step ATT sequences.

| scenario | policy | action seqs equal | ATT arrays `np.array_equal` | max abs diff | rows |
|---|---|---|---|---|---|
| cf_hz1x1 | maxpressure | True | **True** | 0.0 | 61 |
| cf_hz1x1 | random | True | **True** | 0.0 | 61 |
| cf_grid4x4 | maxpressure | True | **True** | 0.0 | 61 |
| cf_grid4x4 | random | True | **True** | 0.0 | 61 |
| cf_cologne3 | maxpressure | True | **True** | 0.0 | 61 |
| cf_cologne3 | random | True | **True** | 0.0 | 61 |

**Sample: 3 scenarios × 2 policies × 61 rows, 6/6 cells bit-identical.** The action sequences being
equal is what makes this a comparison of the same trajectory rather than of two different runs.

Two supporting facts read out of the source and confirmed by the same run:

- It is the **registered, survivorship-free** metric, not the engine's biased one.
  `envs/cityflow_env.py:269-272` reads `self._metrics.get("average_travel_time")` and falls back to
  `self._eng.get_average_travel_time()` **only when `self._metrics is None`** — i.e. when the whole
  metrics pipeline is off, which `offline/collect.py::_require_lane_arrays` already refuses to
  collect from. The condition is *not* "is ATT in the requested set".
- The computation is safe for a non-requested metric **on this backend specifically**. Sections 1–3
  of `metrics/cityflow.py::_run_step_hooks` (departure times, distance/wait accumulators, completed
  vehicles) run **unguarded**; the only `_requires_any` gate in that file is at `:216`, on the
  episode-cumulative waiting-time integrals, which `_average_travel_time` does not read.
  `metrics/base.py::get`'s docstring warns that a non-requested metric "will reflect only what was
  tracked" — for `average_travel_time` on CityFlow, everything it needs *is* tracked.

### 0.2 ❌ ATT is NOT monotone non-decreasing — the brief's original test was false

| source | episodes | non-monotone | earliest drop | median first drop | worst step |
|---|---|---|---|---|---|
| `datasets_att/` (real corpus, since deleted) | **407** | **407 / 407** | row **4** of 361 | row 14 | −6.00 |
| live envs (3 scenarios × 2 policies) | 6 | **6 / 6** | row **7** of 61 | — | −3.67 |

Withdrawn by the Master chat in BRIEF_08 §8. Mechanism: `metrics/cityflow.py::_average_travel_time`

**Evidence provenance.** `datasets_att/` was deleted from the working tree by `7dc9928` (it was
1249 files tracked in HEAD). The 407-episode measurement is therefore not re-runnable from the
current tree; it is reproducible from `7dc9928~1`. The 6-cell live measurement is re-runnable.

### 0.3 ✅ The env's metric key set is derivable, purely, before `reset()`

The C8 guard and the migration both need "the metric key set this env will put in `info`", without
an `info` dict in hand. Verified:

```python
m = env.metrics                      # public property, envs/base_traffic_env.py:649-652
sorted(n for n in m.requested if m.REGISTERED[n].compute is not None)
```

- `env.metrics` is **already populated before the first `reset()`** (measured: `env.metrics is None`
  → `False` on a freshly constructed CityFlow env).
- The derived list **equals `sorted(info["metrics"].keys())` exactly** (measured, both before and
  after reset).
- It is equal **by construction**, not by luck: `metrics/base.py::compute_all` builds
  `{n: self.get(n) for n in self._requested if self.REGISTERED[n].compute is not None}` — the same
  filter.
- It touches no engine call, so it is safe to run at `load()` time on an unreset env.

### 0.4 ✅ Training-config and collection envs derive the same metric set

The migration derives keys from the **recorded training config**; the guard checks them against a
**collection** env. Those two env configurations differ (`local_reward_fn`: `None` vs
`queue_length`; `global_reward_weight`: `1.0` vs `0.0`). Measured: both derive
`['number_of_all_halting_vehicles_for_the_last_time_step_in_simulation']` — equal. If they had
differed, every MAPPO collection would already have raised, so this is a consistency check rather
than a discovery, but it is now measured rather than assumed.

### 1.1 Implementation

| change | where |
|---|---|
| `FORMAT_VERSION = "1.1"`; add `SUPPORTED_FORMAT_VERSIONS = ("1.0", "1.1")` | module constants |
| `self._obs_att_per_step: list[float] = []` | `_clear_episode` |
| require the key, `LoggerStateError` naming C2 if absent | `_check_schema` |
| `append(float(info["average_travel_time"]))` — the read, unchanged | `_record_observation` |
| `"att_per_step": _rows_1d(..., np.float32)` | `_build_arrays` |
| `att_per_step: np.ndarray \| None` | `Episode` |
| accept both versions; `None` for v1.0 | `load_episode` |

**Read strictly (`info[...]`, not `.get`).** C2 mandates the key and all three backends emit it
unconditionally (`cityflow_env.py:269`, `sumo_env.py:316`, `moss_env.py:681`). A `.get(..., nan)`
default would turn a schema violation into a column of NaNs discovered at P4.

**Placed in `_record_observation`, which is the single observation write path** — so ATT gets a
`T+1` row from the same callback as `vehicle_count`/`sim_time` automatically, and cannot drift out
of alignment with them without breaking their tests too.

**Deliberately NOT added to `_episode_digest`.** The digest stays over `action` + `global_reward`.
Two reasons: (a) D3's validation gate compares `episode_sha256` between the v1.0 and v1.1 corpora,
which is only meaningful if the digest covers the same bytes; (b) the digest is P2.4's
duplicate-trajectory detector, and ATT is a function of the trajectory, not part of its identity.
**This will be stated in the docstring**, because a future reader will otherwise reasonably assume
every stored array is digested.

**`Episode.average_travel_time is None` for v1.0.** Confirmed compatible with the next task:
`BRIEF_09` (P3) line 18-19 says "gate the ATT field on `format_version`", so `None` is the contract
P3 already expects.

### 1.3 Fixture changes — load-bearing, per BRIEF_08 §2 as amended

`FakeTrafficEnv` currently hardcodes `average_travel_time: 12.5` at top level **and** inside
`metrics`. Both properties are wrong for this task:

1. **Script a non-monotone sequence.** A constant satisfies every ordering property vacuously, and
   would additionally hide a row-misplacement bug (any permutation of a constant is that constant).
   Non-monotone rather than merely varying, so the fixture matches measured reality (§0.2).
2. **In float32-exact increments (multiples of 0.25).** `test_global_observation_content` asserts
   `ep.metrics[t].tolist() == expected` with `==`, so a value like `12.6` would fail on the
   float32 round-trip. This is a real constraint discovered by reading that test, not a stylistic
   choice.
3. **`metrics["average_travel_time"]` gets a DIFFERENT value from the top-level key.** Without
   this, "the logger read `info['metrics']['average_travel_time']` instead of
   `info['average_travel_time']`" is an *invisible* mutation — the two are equal on a real env.
   The fixture deliberately diverges from real-env behaviour to make that mutation detectable, and
   a comment will say so, because a later reader would otherwise file it as a fixture bug.

Also `test_alignment_block_present_in_docstrings`: `'"1.0"'` → `'"1.1"'`, plus assertions on the
new ATT block. **Disclosed in the Return Packet as a changed test** — the change tracks an
intentional spec bump, not a failing implementation.

### 2.3 Patch content (exactly the authorisation, nothing more)

`save()` gains one key:

```python
"global_metric_keys": (None if self._global_metric_keys is None
                       else list(self._global_metric_keys)),
```

`load()` gains a check **before** `self.learner.load_state(...)`, so a rejected checkpoint leaves
the agent's in-memory state untouched (the filesystem-mutation barrier applied to object state):

| checkpoint state | env state | behaviour |
|---|---|---|
| key absent | any | **loud warning** — pre-migration checkpoint, names the migration script |
| key present, `None` | any | **loud warning** — saved before features were ever built |
| key present, list | env exposes no metrics | **loud warning** — cannot check |
| key present, list | sets equal | silent, no behaviour change |
| key present, list | sets differ | **`ValueError`** naming both sets and the symmetric difference |

Presence is tested with `"global_metric_keys" in payload`, **not** `payload.get(...) is not None`:
the two cases collapse under `.get` and only the first is a pre-migration checkpoint.

`self._global_metric_keys` is **not** assigned from the checkpoint. It would be provably a no-op
once set equality holds (both sides are `sorted(...)`), and the authorisation says "no behaviour
change" — so the no-op is left undone rather than argued for.

Env-side derivation is §0.3's expression, wrapped in one private module-level helper.

### 2.4 The acceptance criterion

  already a dependency), plus a fake metrics object exposing `requested` and `REGISTERED` with the

- **Control — the existing width guard is untouched:** different *count* still raises the original

- **Control — this is the case the old code could not see:** the same-count swap loads *silently*

### 2.6 Migration — `offline/migrate_mappo_checkpoints.py` (ours)

CLI, `--dry-run` **by default**, `--apply` to write.

Per checkpoint: run name = **inner** directory (§0.5) → `experiments/configs/<run_name>.json` →
env entry matching the filename's scenario prefix (`cf_hz1x1__mappo__seed101.pt` → `cf_hz1x1`) →
build env via the frozen `experiments.config` + `experiments.envs.make_env` → derive keys (§0.3) →
close env. Cached per `(run_name, env_id)`, so 60 checkpoints cost at most a handful of engine
constructions.

The brief's three verification requirements:

1. **Self-consistency against the checkpoint's own witness** — `len(keys) == global_feature_dim - 2`.
   Fails the whole run, before any write.
2. **Round-trip** — every written file is re-loaded and its keys compared.
3. **Derivation, not transcription** — keys come from the recorded training config. No literal
   anywhere in the module. Enforced by a test that greps the module source for the metric name.

**Filesystem-mutation barrier:** every checkpoint is loaded and validated, and the full plan built,
**before the first write**. Writes go through a temp file + `os.replace`. A checkpoint already
carrying a *different* `global_metric_keys` aborts the run rather than being overwritten.

**Backup before the first `--apply`** (BRIEF_08 §9, added 2026-08-07). The migration rewrites all 60
`.pt` files **in place** — the only irreversible step in this task, and `datasets/`'s manifests
record the *pre*-migration `checkpoint_sha256`. `output/checkpoints/` is copied to
`output/checkpoints.pre_c8_migration/` first, and the script **refuses to `--apply` if that
directory does not exist**, so the barrier is mechanical rather than a line in a runbook.

Tests (`tests/test_migrate_mappo_checkpoints.py`) use synthetic `.pt` files in `tmp_path` and inject
the derivation through a seam so they need no simulator; the real derivation is exercised by an
actual `--dry-run` over the 60 checkpoints, whose output is pasted.

## 8. What the next task (P3) may assume

- `Episode.att_per_step` is `np.ndarray` `(T+1,) float32` on v1.1, `None` on v1.0; gate on
  `Episode.format_version`, exactly as `BRIEF_09` already specifies.
- Row `T` is `att_horizon`, the A1 primary metric. Row `t` is the network state on arrival at
