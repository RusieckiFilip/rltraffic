## Context

P1 builds the component that records trajectories to disk while an existing policy runs — the corpus
the offline MADT (P3) will train on. `offline/` does not exist yet; this task creates it. Nothing in
the repo writes `.npz` or `manifest.json` today (only `hashlib.sha1` in `experiments/runner.py:51`,
unrelated).

The whole task hinges on one convention, verified against `envs/base_traffic_env.py:585-607`
(apply phases → advance sim `:593` → `metrics.update()` `:599` → reward `:602` → `info` `:603`):
both the reward and the `info` returned by `step t` describe the state **after** step `t`. Getting
this off by one silently shifts every returns-to-go the MADT trains on.

## Design decisions (each one is a place an off-by-one could hide)

**Ordering.** `ix_ids` follows `env.intersections` order, **not** lexicographic — per your GATE-1
answer. C1 says the action vector is ordered by `[ix.id for ix in env.intersections]`, so
`ix{i}_action` ≡ `action[i]` with no remap table. Stated explicitly in the module docstring.
`lane_ids` *is* sorted lexicographically (brief §3), frozen at `on_reset`.

**One write path per array.** `on_reset` and `on_step_result` both call a single private
`_record_observation(info)`. There is no `if terminated: also write` branch — row `T` is just the last
`info`. `on_action` writes only the action and asserts `info["step"]` equals the last recorded step.

**State machine.** `IDLE →(on_reset)→ AWAIT_ACTION ⇄(on_action / on_step_result)⇄ AWAIT_STEP`;
`finalize_episode` legal only from `AWAIT_ACTION` (a dangling `on_action` is an error). Violations
raise `LoggerStateError(RuntimeError)`.

**Deliberate non-use of a C4 helper.** `Utils.reward_for_intersection` is **not** used for
`local_reward`. Its fallback chain (`agent/utils/utils.py:69-75`) silently substitutes the *global*
scalar reward when `payload["reward"]` is absent — which is exactly the case the brief requires to be
`np.nan`. Using it would fabricate per-intersection rewards for envs with no `local_reward_fn`.
Read directly from `next_info["intersections"][id]["reward"]`, key-absence → NaN. Flagged in the
Return Packet as a rule-5 exception.

**Helpers that are used:** `Utils.state_from_info`, `Utils.infer_action_counts`,
`Utils.extract_valid_actions`, `Utils.scalar_reward`, `Utils.extract_per_intersection_info`,
`Utils.seed_everything` (in `collect.py`).

**Consequences of the Phase-1 findings:**
- `info["metrics"]` is conditional (`envs/cityflow_env.py:279`) → read with `.get("metrics", {})`;
  `metric_keys` frozen as `sorted(...)` at `on_reset`, mirroring `agent/MAPPOAgent.py:629`. An empty
  freeze is legal; a *change* mid-episode raises.
- `Utils.extract_valid_actions` returns indices, not a mask (`agent/utils/utils.py:78`) → the logger
  builds the `np.bool_` mask itself, width = `n_actions[i]`, `True` = legal.
- `Utils.infer_action_counts` needs `env.action_space`, which only exists after `_setup_spaces()`
  (`envs/base_traffic_env.py:309`) → called in `on_reset`, not `__init__`, and via
  `getattr(env, "action_space", None)` so the `ix.num_phases` fallback path works.
- `time_in_phase` is `int` at source (`envs/phase_control.py:176`) → cast to float32 per C6.

**Hashing.** `episode_sha256` = sha256 over `ix{i}_action` bytes in intersection order, then
`global_reward` bytes. Arrays are viewed as explicit little-endian (`"<i8"` / `"<f4"`) before
`.tobytes()` so the digest is not platform-endianness-dependent — otherwise P2.4's duplicate detector
would disagree across machines. `lane_ids_sha256` = sha256 of `"\n".join(lane_ids)`.

**Manifest.** Rewritten in full on each `finalize_episode` to `<out_dir>/.manifest.json.tmp`, then
`os.replace` → `manifest.json`. Docstring states one `out_dir` belongs to one process.
`flow_draw` uses the `-1`-for-absent sentinel in *both* the npz scalar and the manifest entry — one
convention, not two. `Episode.flow_draw` exposes the raw `-1`, it does not remap to `None`.

**No pickles.** Only numeric and unicode arrays are stored, so `np.load` works at its safe default
`allow_pickle=False`.

### Module docstring — three mandated statements (GATE-2 amendments 2 and 3)

Beyond the verbatim alignment block and the format version, `offline/trajectory_logger.py`'s module
docstring must state:

1. **`ix_ids` is in `env.intersections` order**, so `ix{i}_action` ≡ `action[i]` (C1).
2. **Every episode end is a time-limit truncation.** `terminated` is hardcoded `False`
   (`envs/base_traffic_env.py:604`); only `truncated = self._step_count >= self.max_steps` (`:605`)
   ends an episode. There is no true terminal state in this platform, so downstream RTG code cannot
   use `terminated` to tell a genuine absorbing state from a time limit.
3. **`local_reward` is COMPOSITE, not a purely local signal.** Verified at
   `envs/base_traffic_env.py:204-219`:
   `global_reward_weight * global_reward + local_reward_fn(local_metrics[j])` — the global term is
   `:214`, the local term `:217`. Downstream RTG code **must not double-count the global part** by
   summing `global_reward` and `local_reward`.

### Two small strengthenings beyond the brief (veto either at GATE 2)
1. `format_version` is stored **inside each `.npz`**, not just the manifest, so P2.4's linter can
   hard-fail per-episode as C6:123 requires.
2. A later episode in the same run whose `lane_ids` disagree with the run-level `lane_ids_sha256`
   raises at write time rather than being left for the linter. One `out_dir` = one scenario; a run
   containing two topologies is broken, and failing at collection time is cheaper than after 20 h of
   simulation.

## `offline/collect.py`

Env construction **reuses `experiments.envs.make_env`** (per your GATE-1 answer): `collect.py` builds
a frozen `EnvSpec(id, backend, paths, settings)` (`experiments/config.py:74-79`) with
`settings = dict(SETTING_DEFAULTS) | cli_overrides`, so the kwarg table lives in exactly one place and
cannot drift. `SETTING_DEFAULTS`, `BACKENDS`, `CONTROL_MODES` are all public names in
`experiments/config.py`. No frozen file is modified — only imported.

Flags: `--env-config`, `--backend`, `--policy`, `--checkpoint`, `--epsilon`, `--episodes`,
`--base-seed`, `--max-steps`, `--delta-time`, `--out-dir`, plus `--control-mode`,
`--global-reward-fn`, `--local-reward-fn`, `--state-features`, `--metrics`, `--thread-num`
(the brief's `run_metadata` requires recording these, so they must be settable), and
`--map-file`/`--person-file` for the MOSS backend.

`POLICIES: dict[str, Callable]` with exactly four entries — `maxpressure`, `random`, `mappo`,
`mappo_eps` — each a factory `(env, args, rng) -> act_fn(info) -> np.ndarray`. `MaxPressureAgent`
takes `act(info)` only and is **not** a `BaseAgent` (`algorithms/max_pressure.py:11,24,28`), so the
adapters are per-policy rather than one uniform call. Episode `i` uses
`engine_seed = base_seed + i`; `flow_draw` is always `None` in P1. One line printed per episode plus a
final summary (episodes, total steps, mean return).

**Empty-lane-set guard (GATE-2 amendment 1).** After the first `on_reset`, `collect.py` hard-fails if
`len(lane_ids) == 0`, with a message naming `--metrics`. SUMO and MOSS return `{}` lane dicts when the
metrics pipeline is off (`envs/sumo_env.py:301`, `envs/moss_env.py:653`); a corpus with no lane arrays
silently violates C6 reward-agnosticism and would only surface at P3. **The guard lives in the
collector, not the logger** — the logger still records `L = 0` honestly, because refusing to log is a
collection-policy decision, not a format decision. Implemented as a module-level
`_require_lane_arrays(lane_ids, backend)` so it is testable with no backend installed.

## Explicitly NOT doing (scope fence, from the brief §SCOPE)

- The Decision Transformer / MADT.
- The dataset loader (P3) — only `load_episode` as its reload contract.
- The flow randomizer (`flow_draw` is plumbed but always `None` in P1).
- The corpus linter (P2.4) — only the hashes it will consume.
- Any new control policy. **No fixed-time controller** — that is P2.5. The registry ships four
  entries (`maxpressure`, `random`, `mappo`, `mappo_eps`); `fixedtime` and `dqn` are deliberately
  absent so they can be added later without touching the CLI.
- No modification to any frozen file. `experiments.envs.make_env` and `experiments.config` are
  imported, never edited.
- No new dependencies (numpy + stdlib; pytest for tests).

## Open questions — CLOSED at GATE 2 (Master-chat ruling, 2026-07-26)

All three are answered and recorded in the master plan. Nothing in P1 changes because of them; they
are kept here as the audit trail and are restated in the Return Packet.

1. **`terminated` is hardcoded `False`** (`envs/base_traffic_env.py:604`); only
   `truncated = self._step_count >= self.max_steps` (`:605`) ends an episode. Every corpus episode
   carries `terminated == False`. Not fixed in P1 — the logger records both scalars faithfully as C6
   requires. **P4 needs this for RTG at episode boundaries:** there is no true terminal state, so
   every episode end is a time-limit truncation. → now also mandated in the module docstring
   (amendment 2).
2. Lane dicts are `{}` on SUMO/MOSS with the metrics pipeline off (`envs/sumo_env.py:301`,
   `envs/moss_env.py:653`); CityFlow falls back to a direct engine query. → addressed by the
   collector-side guard (amendment 1); the logger's honest `L = 0` behaviour is unchanged.
3. C2 presents `info["metrics"]` as unconditional; both the global and per-intersection forms are
   gated on the metrics pipeline. Wording fix for the contract at its next version bump, not P1's job.
