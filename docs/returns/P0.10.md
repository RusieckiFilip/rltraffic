Quantified in this session:

| quantity | value |

reproduce bit-exactly or to *n* ulp across machines is a research decision.** ⚠️ It is also, exactly,
the risk `BRIEF_23` §4 named: *"we report differences of 5.68e-14 and treat float reduction order as
evidence … while the environment producing those numbers is specified by lower bounds only."*
**The first cross-machine check this project has ever run found it on run 1.**
**Until it is ruled on, CI is red.**

**(a) My own violation.** This packet originally quoted the Polish fixture word verbatim while

**(b) The defect that hid it from me — `scripts/check_english.sh` returns exit 0 for any file that is
not at the repository root.** I ran `bash scripts/check_english.sh docs/returns/P0.10.md` before
committing, got exit 0, and believed it. It was vacuous. Measured, same guard, same session:

```
$ bash scripts/check_english.sh README.md                 # root, has a finding at :30
BLOCKED: non-English text found. ... README.md:30
  exit=1
$ bash scripts/check_english.sh docs/returns/P0.10.md     # nested, HAD a finding at :125
  exit=0   <-- FALSE CLEAN
$ bash scripts/check_english.sh                           # repo-wide run sees it
docs/returns/P0.10.md:125
```

**Mechanism, localised to one line.** `check_english.sh:47` builds the file list as
`git ls-files -z -- "$@" "${EXCLUDES[@]}"`. Combining a **nested** positive pathspec with the exclude
pathspecs returns nothing on git 2.53.0:

```
$ git ls-files -- docs/returns/P3.md                      -> 1 file
$ git ls-files -- docs/returns/P3.md ':!CityFlow/'        -> 0 files
$ git ls-files -- README.md         ':!CityFlow/'         -> 1 file
```

`FILES` is then empty and line 52 (`[ "${#FILES[@]}" -eq 0 ] && exit 0`) reports clean. Reproduced in
both this worktree and the main one, so it is not a worktree artifact.

**Why this matters beyond my packet: the PostToolUse hook uses exactly this mode.**
`claude_guard.sh --lang-only` passes changed paths, so the English rule has been effectively
unenforced on every file outside the repository root — while appearing to pass. The repo-wide
invocation (no arguments) is unaffected, which is why the recorded baseline of 5 has always been right.

**NOT FIXED HERE, deliberately.** `BRIEF_23` §5 puts *"any change under `scripts/`"* out of scope, and
`check_english.sh` is a `FROZEN_EXCEPTIONS` file whose repair route is a patch in `docs/patches/`
plus a human applying it (`CLAUDE.md` §1). Repairing it would also change what the hook catches
repo-wide, which is a decision with its own blast radius — it belongs with **P0.9**, which already
owns this script. Written up here so it cannot be lost; see §12.

  `[tool.setuptools.packages.find].include`** or `tests/test_packaging.py` fails — by design.
* **Every push runs CI.** A task that adds skipping tests must expect the ceiling gate to fire, and
  the correct response is to re-measure and commit the new ceiling with its reason — **never to widen
  it with slack**. **P5.1's merge is expected to breach it (≈ +25 skips) and is mandated to
  re-measure in the merge commit.**
* The guard baselines are 16 and 5 keyed by `(file, rule)`. A new test file with a bare
  `pytest.raises` will turn CI red, and the fix is the test, not the baseline.
* CI is red on `task/p0.10-reproducibility` for the reason in §5 — **a merge would carry a red
  pipeline onto `main`** unless that is ruled on first.
