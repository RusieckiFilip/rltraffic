## 3. ⭐ The `fixedtime` collapse — a scientific finding

On grid4x4's `fixedtime` tier, **4 of 7 arms carry distinct per-episode ATT vectors**:

- `behaviour@fixedtime` ≡ `dt_nomix@fixedtime` ≡ `dt_spatial@fixedtime`
- `bc@fixedtime` ≡ `bc_top10_perix@fixedtime`

**It is confined to `fixedtime`.** Re-measured over the full 100-draw × 5-seed vectors:
`mappo1000` 6/6 distinct, `maxpressure` 7/7, `random` 6/6.

Two consequences, and they point in opposite directions:

1. **It is evidence the pipeline works.** Cloning a deterministic clock policy returns the clock;
   `dt_nomix` and `dt_spatial` reproducing `behaviour` exactly on a fixed-time tier is what a correct
   imitation pipeline should do on a deterministic teacher.
2. **It removes all discriminating power from P5.2's `fixedtime` rung.** P5.1's P2a contrast is
   `mean(ATT_spatial − ATT_nomix)`, which on that rung is **identically zero by construction, not by
   measurement**.

⚠️ **Correction to my own earlier report:** on a three-draw sample I said `bc`, `bc_top10` and
`bc_top10_perix` were all identical. Over the full vectors `bc_top10` separates; only `bc` and
`bc_top10_perix` coincide. The three-draw read was too small and the full-vector measurement
supersedes it.

### BINDING on the verdict layer

Every re-derived contrast reports, per tier, whether the arms it compares are distinct at all.
**"The tier cannot discriminate" is the honest statement; "no difference was found" is not** — the
second implies a measurement that could have come out otherwise, and on such a tier it could not.

Implemented as `contrast_discriminability(...)`, and enforced by
`assert_contrast_reports_discriminability(...)`, which refuses any block carrying a verdict or
outcome beside a tier without its discriminability. The rule is only binding because something
checks it.

## 4. The reproduction acceptance test, and its arm-dependent power

Every re-derived cell must reproduce its committed `att_ours` **exactly**; a cell with no committed
value at any grain is UNVERIFIED and excluded from every verdict. A checkpoint sha256 proves a file
is intact, not that it is the right file for that arm — and the episode is rolled anyway, so the
stronger check is also the free one. It caught two real failures.

⚠️ **Its power is ARM-DEPENDENT, and this belongs beside the test rather than in a footnote.**
`grid4x4/bc@fixedtime` is **seed-invariant**: all five seeds produce bit-identical committed ATT on
every draw although the five checkpoint files are md5-distinct. A seed mix-up there is
**undetectable — and harmless**, because the numbers are identical. Within the collapsed groups of
§3 the same holds across arms. The test remains correct; it cannot discriminate where the arms
themselves do not.

Two further guards fired unprompted while probing this: `agent/OfflineBaselines.py` refuses a `bc`
checkpoint loaded as `iql` on the format string, before any rollout.

### The standing rule this produced, and why

**Two of my edits caused the next failure**: a slice rewrite that removed the entry point, and a
string replace whose match I never asserted. **Both times the tests passed afterwards**, which is
what made me confident.

🔒 **After ANY mechanical edit — slice rewrite, `sed`, string replace — diff the file against `HEAD`
and read what actually changed before claiming the edit is done. Not "the tests pass": the diff. An
edit you did not look at is an edit you did not make.**

This is `PROJECT_PLAN` §7's existing rule generalised: *a tool that restores state must restore only
what it changed* — and the same applies to a tool that writes it.

Defects 7, 8 and 9 are one class: **a declaration that no longer matches the artifact, invisible
because nothing checked it.** All three are now checked by machine rather than by reading:
`test_the_module_actually_runs_as_a_command_line_program` (subprocess, not in-process `main()`),
`test_every_name_a_module_exports_actually_exists`, and
`test_every_offline_module_with_a_main_can_actually_be_run`, which scans the whole package so the
next instance is caught wherever it happens rather than only in my own files.

**Both launch failures were in ORCHESTRATION and both passed my tests.** After defect 1 I wrote 17
unit tests, re-introduced the defect, and **all 17 passed** — the functions were each correct and the
bug was in how `main` composed them. Only a test driving `main` as multiple workers catches it; that
test now exists and fails when the defect is re-introduced.
