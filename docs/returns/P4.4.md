### 4.4 The IQL sweep decision, made before the first gradient step (§9.2)

**No sweep.** Written into `docs/plans/p4.4.md` §3.5 at commit `3cf3344`, with a reason that is
analytic rather than budgetary and that does not depend on any P4.4 number:

1. **β appears in no value loss at all**, so the authorised criterion (training-split expectile/TD
   loss) is *exactly insensitive* to it.
2. **Selecting β on the policy loss is provably degenerate**: the AWR weights shrink toward 1 as
   β → 0, so the loss falls monotonically and the criterion picks the smallest β in any grid — at
   which point IQL's policy extraction **is** plain BC, and the sweep collapses the arm into the one
   it exists to be compared against.
3. **τ defines the expectile loss**, so two τ values are values of two different objectives;
   substituting Q's TD error is worse, because a smaller τ makes V easier to fit and biases the
   criterion toward the SARSA-like regime IQL exists to escape.

**What shipped instead of a sweep**, computed on training data only and therefore selecting nothing
— the degeneracy diagnostic, which shows the transplant did **not** degenerate:

| diagnostic (5 seeds) | value |
|---|---|
| AWR weight median | 0.009 – 0.077 |
| AWR weight q90 | 31.5 – 100.0 |
| fraction clipped at 100 | 7.7 % – 11.4 % |
| fraction below 0.01 | 37.8 % – 50.5 % |
| effective sample size | 11.3 % – 17.0 % |
| advantage std | 2.78 – 2.92 |
| agreement with the behaviour action | **94.6 % – 95.0 %** |

Against BC's **99.75 % – 99.84 %** and %BC's **99.84 % – 99.87 %**: IQL departs from the behaviour
policy on about 5 % of states, and those departures are what buy its 2.11 ATT over MAPPO@1000.

### 6.2 ⚠️ A REAL DEADLOCK IN THE EVALUATION PATH — and it is P4's path too

Gate A's first attempt **hung**: after roughly 600 rollouts the process stopped consuming CPU
entirely (`utime` frozen across a 5-second sample) with **all 32 OS threads parked in
`futex_do_wait`**, while wall clock advanced. It ran 25 minutes and would have run forever.

This is the liveness class `experiments/runner.py` pins against (P0.3-fix: "**the pin is a liveness
fix, not a performance fix**"), and **`offline/dt_gate.py` deliberately does not import that module**
— by design, since importing it pins the calling process as a global side effect — so nothing was
pinning this path. **P4 ran the same code unpinned on the same machine and did not hang**, which is
what makes this a latent hazard rather than a broken build.

Before adopting the fix I checked the thing that would have made it unusable — whether one thread
changes any number. **It does not**: six cells across MADT, MAPPO@1000 and MaxPressure reproduced
bit-identically at one thread, and then all 1100 did. It is also **~5× faster** (1.05 s/episode
against ~5 s). `pin_torch_threads` is applied in `main()` only, never at import, and
`torch_num_threads = 1` is recorded in every artifact this task emits.

**For the coordinator:** P4's Return Packet §6.4 records seed 505 training for **14,018 s against
202–356 s** for the other four, attributed to "almost certainly a laptop suspend". I cannot
diagnose that from here and I am not claiming it was this — that run was CUDA training, not CPU
rollout — but the same machine has now demonstrably produced an unbounded torch-thread hang, so the
suspend hypothesis is no longer the only one on the table.

**IQL's transitions are built with `offline.trajectory_logger.load_episode`**, not from

Guarded by the loader cross-check **and** by the raw-`np.load` row-`T` test the §8.4 correction
required — and M3 shows only the second one has any power there.

## 8. Limitations of what I shipped

1. **The comparison is one scenario, one backend, one intersection, one tier** — `cf_hz1x1`,
   CityFlow, `mappo1000`. Expert-only data has the narrowest state coverage in the ladder; nothing
   here bears on off-distribution behaviour, and nothing here is a ladder result.
2. **DT − baseline is a combined difference** (§0). No decomposition is offered or implied.
3. **The reported models have not converged** on the declared budget: the plateau criterion fails
   5/5 for BC and IQL and holds 4/5 for %BC. The DT was reported the same way (0/5). A longer budget
   could move any of these numbers; the registered design forbids me from choosing a better point.
4. **IQL is untuned by design and by ruling.** Its *winning* is not weakened by that, but no claim
   about IQL-in-general follows from a single untuned configuration, in either direction.
5. **%BC's advantage may be a filter effect on a narrow tier.** The top-10 % slice is 20 streams of
   200 spanning −5762 to −6419, and %BC trains 40,000 steps on 7,200 windows — 355 epochs. It
   reaches 0.001 training loss and 4/5 plateau, so some of its margin may be memorisation of an
   easier subset rather than a return-filter effect that generalises. **I did not test that**; a
   %BC-at-other-fractions sweep would, and it is out of this task's fence.
6. **The CIs over 500 episodes pool two variance sources** (5 seeds × 100 draws). Per-seed means are
   in §9 so the seed component is visible; the paired tests correctly use per-draw means.
7. **Action masking is untested as a capability** on this corpus (all-`True`), and M18 documents
   that BC's training mask is an equivalent mutant here.
8. **One thread is now the reported configuration** for evaluation. It reproduces P4's 16-thread
   numbers exactly on 1100 cells, so nothing is at risk today, but a future comparison against a
   16-thread number should re-check rather than assume.
