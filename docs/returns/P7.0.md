## 11. Tests I changed, disclosed in full

**One test specification was corrected, before implementation and not after a failure.** The first
draft of `test_signed_distance_is_negative_exactly_when_a_criterion_fires` asserted
`fired == (signed_distance < 0)` for **all** criteria. **That is false at an exact boundary** for the
two criteria whose declared inequality fires *on* the threshold (`B1`: `Δ ≤ 0`; `B3`: `count ≥ 9`) and
for `A1`, which is `B1`'s complement: there `signed_distance == 0.0` while `fired is True`.

Diagnosis: my own specification bug, found while designing the implementation, with **no implementation
in existence** and therefore no failing test being accommodated. It was replaced by something
**stronger**, not weaker:

- `test_fired_is_recomputable_from_statistic_threshold_and_comparison` — recomputes `fired` from the
  row's own `statistic`, `threshold` and `comparison` using `operator`, over a 7-case sweep (≥50 rows).
  This covers the boundary exactly.
- `test_signed_distance_sign_agrees_with_fired_away_from_the_boundary` — the sign invariant as an
  implication, with the limitation written into its docstring.
- `test_the_boundary_firing_criteria_are_exactly_b1_b3_and_a1` — pins the exempt set so it cannot grow.

**No existing test was edited or deleted. No assertion was weakened.** Mutation M10 confirms the
