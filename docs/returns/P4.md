**`mappo1000`.** The threshold is defined relative to the best online policy, so only the
105–107 tiers hold trajectories at the required quality; a failure on a weaker tier would be

**Two things this result therefore does NOT say**, carried from the §8 ruling verbatim:
1. Passing demonstrates **pipeline capability, not that sequence modelling beats imitation.**

## 6. Deviations, disclosures and findings

### 6.1 Four test changes, in full, with diagnoses

1. **Three checkpoint tests' setup** (`tests/test_dt_agent.py`). They built an agent that had
   never seen an `info`, so the lazily-built model did not exist and `save()` raised. **Cause: an
   implementation decision made after the tests** — the model is built lazily from the observed
   state width, mirroring `MAPPOAgent.ensure_initialized`, because an env does not expose that
   width. Setup now passes `state_dim=`; **no assertion changed**. The precondition is pinned by a
   **new** test (`test_saving_before_the_model_exists_raises_...`) rather than absorbed silently.
2. **The Wilcoxon null case.** I wrote `base` vs `base + 1e-9` as a "null". It is not one: 100
   differences of a single sign is the *most extreme* signed-rank outcome, and `p = 1.9e-18` was
   the **correct** answer. My premise was wrong, not the code. Replaced with two independent
   samples, and the property I got wrong is now pinned by its own test
   (`test_wilcoxon_detects_a_tiny_but_perfectly_consistent_shift`).
3. **`stack_dataset` group handling.** The test addressed stacked rows by dataset index, which is
   only valid for a single-group dataset; the fixture has two. **The code was under-specified** —
   it now takes an explicit `group=` and returns `item_index`, which `cf_cologne3` (three groups)
   will need. The test's index arithmetic follows; the assertion is unchanged, and a new test
   pins that stacking a multi-group dataset without naming the group raises.
4. **The `local_reward_fn` test's manifest** was incomplete, so it passed on the *missing-keys*
   error rather than the one it names. Manifest completed; a separate new test now covers missing
   keys.

## 8. Limitations of what I shipped

1. **The reported model has not converged.** The plateau criterion fails at the reported 40,000
   steps on all five seeds. A model reported before its loss plateaued may be under-trained; the
   registered design forbids me from choosing a better point, and a second raise is the
   coordinator's to authorise.
2. **A pass on `mappo1000` says nothing about stitching.** BC would plausibly do the same; that is
   exactly what P4.4 exists to measure. Nothing here should be read as a sequence-modelling claim.
3. **Narrowest state coverage in the ladder.** Expert-only data, so nothing here bears on
   off-distribution behaviour.
4. **Action masking is untested as a capability** on this corpus by construction (all-`True`), and
   I make no claim about it. It is exercised only by synthetic masks.
5. **One RTG rule, not a sweep.** `target_rtg = -5762.0` (max training-split episode return),
   `rtg_scale = 9991.0`. P4.3 owns the sweep; a different conditioning rule could move the number.
6. **Single scenario, single backend, one intersection.** The `DTAgent` supports N homogeneous
   intersections (contexts keyed by id, tested on a 2-intersection stub) but only the
   1-intersection path is exercised by real data.
7. **The Wilcoxon is new code on a reported statistic**, tested against hand-computed values but
   not against a reference implementation, because scipy is absent.
8. **CIs over 500 episodes pool two variance sources** (5 training seeds × 100 draws) into one
   interval. Per-seed means are reported so the seed component is visible; a formal
   variance decomposition is not attempted here.
9. **⚠️ The model is conditioned outside its training support for a fifth of every episode.**
   Found by the independent review, not by me. All training rewards are ≤ 0, so every training
   RTG is ≤ 0 — but at evaluation the RTG is driven by the *observed* rewards from the declared
   start of −5762, and it goes **positive for 75 of 360 decisions (20.8 %)** on the probed
   episode, with the scaled input spanning −0.577 … +0.153. Every episode therefore ends
   conditioned on a return the model never saw. The gate number stands as measured; this is a
   property of the declared conditioning rule and it is P4.3's to study, not something I may
   tune away here.
10. **The declared RTG is not the best RTG**, which is evidence *for* the run rather than against
    it: the reviewer measured `target_rtg = 0.0` → 102.05 and `−3000` → 102.41 on `(101, 1000)`,
    against **106.46** for the declared `−5762`. The reported number is demonstrably not
    RTG-optimised. It also means P4.3 has real headroom to find.
