### 🚨 S1 SURVIVED, AND THE FINDING IS THAT MY OWN DOCSTRING WAS FALSE

`agent/SpatialDTAgent.py`'s module docstring claimed the model's leak-freedom came from *"temporal
runs before spatial in every block"* and stated **"swapping the two sublayers would break it and
the model would still train."** Mutation S1 swapped them and **all 25 tests passed.**

I then measured the actual mechanism by perturbation rather than argument:

```
CLAIM 1 -- perturb node 1 at token position 7, spatial sublayer only:
           positions changed: [7]                    -> strictly POSITION-WISE
CLAIM 2 -- same perturbation, temporal sublayer only:
           positions changed: [7, 8, 9, 10, 11]      -> strictly CAUSAL
```

Since the only operation that moves information across token positions is causal, a peer's
concurrent action cannot reach a prediction **in either sublayer order**. The claim was false; the
code was right; S1 is a genuine **equivalent mutant**.

Corrected in the docstring with the correction labelled and dated, and three tests added: one
pinning each measured property directly, and one pinning the shipped order **explicitly labelled a
reproducibility pin rather than a correctness guard**, so the wrong justification is not
re-derived later. *A plausible structural argument stated in a docstring as if it were load-bearing
is exactly the kind of claim that reaches a methods section unchallenged. It was caught only
because the mutation was run.*

### A4 — an equivalent mutant that grid4x4 alone cannot kill

`undirected = directed | directed.T` → `undirected = directed` survived all 31 grid4x4 tests,
because **grid4x4's directed relation is already symmetric** (every road has a counterpart in the
opposite direction). Same family as `DEFERRED` 37: equivalent on today's data, live on tomorrow's.
Closed with a synthetic one-way roadnet (`X -> Y`, boundary nodes carrying `gt_virtual` exactly as
grid4x4's 16 do), where the relation is asymmetric by construction. Four new tests; A4 now killed.

## What was measured (every number from a command run in this session)

**The adjacency control, and a second route for it.** Restricted to the 16 controllable
intersections, the lane rule gives **48 directed / 24 undirected** edges with degree histogram
`{2:4, 3:8, 4:4}` — the brief's known 4×4 pattern. An independent route reading only road
endpoints (`startIntersection`/`endIntersection`, never lanes or `roadLinks`) gives **the same edge
set, exactly**. The wrong derivation `incoming ∩ incoming` gives **0** edges.

**The trap the coordinator hit, reproduced.** `grid4x4_roadnet_red.json` holds **32** intersections
with `virtual: False` on **all 32**; the discriminator is `gt_virtual`, true on 16. Deriving over
"non-virtual" gives **80 directed / 40 undirected** and a degree histogram of `{1:16, 4:16}` — in
which **every real intersection reads degree 4 and a corner is indistinguishable from an interior
node**. ⚠️ The wrong graph is *uniform*, not obviously broken. *(One refinement on the brief's
description: the 16 extra nodes come out at degree **1**, not degree 0.)*

**A structural finding that strengthens the pairing-key rule.** Reversing the node order is a
**graph automorphism** of the 4×4 grid — a point reflection through its centre — so the relabelled
edge set is equal and the matrix is **bit-identical**. The adjacency matrix therefore *cannot*
reveal that permutation, which is why `node_ids` travel with it and are checked against the data.

   the declared values and the arm ordering is fixed by construction. Verified by three consecutive
