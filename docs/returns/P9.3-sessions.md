## What `train-queue` does now
- **`--hours H`.** The session plans the NEXT pending cells, in order, whose planned seconds sum to at most H hours. The first cell
  is always included, and a later cell that would fit is never pulled past one that does not. It prints the plan, trains exactly
  those cells, and exits 0 with a summary: the cells planned and trained, the next pending cell, and the planned hours left.
- **The planned seconds** are G3b's timing records (`3ea8418`, CUDA): each arm's 2,000-step seconds × 20, plus that process's setup.
  - Per cell: `dt_nomix` 3,503.2, `bc_m` 375.8, `bc_top10_m` 151.4, `bc_top10_perix_m` 144.5, `iql_m` 1,346.1. That is 30.67 h for
    the 100 cells.
  - Each carries the label *"planning estimates … not a measurement of any cell"*.
- **`--max-cells N`.** At least one of `--hours` and `--max-cells` is required. An unbounded queue is refused before any path is
  resolved.
- **The stop file `<output root>/p9_3/STOP`** (for the campaign, `/home/filip/rltraffic/output/p9_3/STOP`):
  - it is checked before each cell, and once it exists the session ends after the cell in flight;
  - a session refuses to start while it exists;
  - the code never creates or deletes it.
- **`run_train_queue`** keeps its behaviour and its two committed tests unchanged. It was refactored onto `pending_training_cells`,
  the half-written-cell refusals, which the session shares.
