## 8. Disclosures, classified

**D-1 — 🚨 One-second offset, found by the instrument on its first real episode.** The pool identity
refused at `t = 3.0`. Measured cause: SUMO reports a departure at `getDeparture + dt`, one value
`1.0` over 600 s and 307 departures — the twin of Gate 0's `first_seen = enterTime + interval`. My
due predicate was one second early. Without the identity it would have shifted every `E_sumo`
contribution by a second, invisibly. Fixed, and pinned by M1.

**D-2 — 🚨 The decomposition residual is an algebraic tautology and is NOT gated on.**
`(P−E)+(W−P)+(att−W)−(att−E)` cancels `P` and `W` identically. Measured: moving `P` by 1e-9 leaves it
at `0.0`; moving `P` by **100** leaves it at `4.44e-15` — non-zero for a purely numerical reason
while blind to semantic error of any size. Gating on `== 0.0` would have looked like a check, been
none, and refused correct data mid-campaign. The gate is the clock-origin **second route** instead.
This is `P5.3b-fix` §2.7's class recurring, degenerate on SUMO because no engine call anchors `E`.

**D-3 — The brief's `1e-9` reproduction test is unsatisfiable against a float32 record.** Amendment
A2's exact form has a detection floor of one float32 ulp. Stated in a test
(`test_the_detection_floor_of_the_reproduction_check_is_one_float32_ulp`) rather than hidden.

**D-4 — Four tests I changed after they failed, each because MY TEST was wrong, none to weaken a
check.** Disclosed in full because the rule is never to edit a test to make it pass:
1. `test_the_decomposition_residual_catches_a_perturbed_term` → renamed to
   `…_is_a_tautology_and_cannot_be_a_check`. It asserted a power the quantity does not have (D-2).
   Replaced by a test of the truth, plus a new test of the check that does have power.
2. `test_align_info_refuses_rather_than_falling_back[wrong-action-count]` — I asserted a **short**
   `avail_actions` must raise. C2 says `avail_actions` are the legal actions *right now*, so a subset
   is normal. The real defect is an out-of-range **index**; the test now uses `[0, 99]` and a new
   control asserts `[0, 3]` passes. The implementation gained the range check it was missing.
3. The pool-identity fixtures in two tests started at `t = 0` under the pre-measurement timing; the
   identity refused them. The fixtures were corrected to the measured convention, not the identity.
4. `test_the_driver_checks_everything_…` matched the string `mkdir -p` inside the refusal *message*
