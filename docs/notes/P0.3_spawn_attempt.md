## Hypotheses (each produces a different symptom)

1. Missing `if __name__ == "__main__":` in the entry point. Under `spawn` the child process
   re-imports the startup module, so without the guard it hits a RuntimeError about bootstrapping or
   recursive process spawning. The most common cause of "it worked under fork, not under spawn".

2. Unpicklable `run_cell` arguments. `fork` copies process memory, `spawn` has to pickle everything.
   A CityFlow engine handle, a lambda, a closure or an env object in the arguments give a
   PicklingError immediately, before any simulation.

3. Output directory collision between workers. Each worker creates its own engine, but if they all
   write replay/logs to the same place there is no readable error — the symptom is corrupted files or
   a hang.
